## 1. 世界图谱的目的是什么

写设定的时候，关系其实是**散落**在各处的：

- 「临江国」这张卡上有个「首都」属性，指向「石头城」卡片；
- 时间线里「青水之战」这个事件，挂了好几张参战卡片；
- 某张卡的正文里顺笔写到「北境」两个字。

这些关系你在编辑时都写下了，但它们**分布在不同的文档里**。
世界图谱做的事，就是**扫一遍全世界的卡片，把这些隐含关系全部抽出来，画成一张「节点 + 连线」的图**。

```
       [临江国] ──引用──▶ [石头城]
           │                  ▲
        正文提及             事件关联
           │                  │
           ▼                  │
        [北境] ────────▶ [青水之战]（时间线事件文档）
```

有了这张图，你能一眼看到：谁和谁有牵连、哪张卡是「枢纽」、哪些卡是「孤岛」。

> 类比：卡片是图书馆里的书，图谱是**借阅关系网**——
> 哪几本书老是被互相引用、哪些书从来没人碰，图上都看得出来。

## 2. 连线的三个来源

图谱里的每条连线都有一个 `kind`，一共三种来源：

| 来源 | kind | 界面叫法 | 规则 |
| --- | --- | --- | --- |
| 引用属性 | `reference` | 引用 | 卡片上 `value_type = "reference"` 的属性值 → 一条线 |
| 事件关联 | `event` | 时间线关联 | 时间线事件挂的卡片 → 一条线（时间是这张图的另一种边） |
| 正文提及 | `mention` | 正文提及 | 卡片正文里写到别的卡片名 / 别名 → 一条线（走自动识别） |

### 2.1 来源一：引用属性（`reference`）

「引用」是一种属性值类型（`VT_REFERENCE = "reference"`）。
当你在卡片上把这个属性设成「指向另一张卡」时，属性里存的实际是**目标卡片的 id**。

```python
# world/normalize.py —— 引用值在解析时带上目标摘要
if prop.value_type == VT_REFERENCE and value:
    target = card.document.world.documents.filter(pk=as_int(value)).first()
    if target is not None:
        extra = {"ref": {"id": target.id, "name": target.name, "type": target.document_type}}
        display = target.name
```

**真实例子：** 「临江国」卡片有一个「首都」属性（引用类型），值指向「石头城」。
于是图谱里就有一条 `临江国 ──引用(首都)──▶ 石头城` 的线。

### 2.2 来源二：事件关联（`event`）

时间线里的事件通过一个多对多关系 `linked_cards` 挂上若干卡片。
图谱把这些关联也算成边，**边的两端是「事件所在的文档」与「被挂的卡片」**。

```python
for event in events:
    for card_doc in event.linked_cards.all():
        add_link(event.document_id, card_doc.id, "event", event.title)
```

**真实例子：** 时间线「青水之战」这个事件挂了「临江国」「北境」两张卡，
就会产生两条 `事件文档 ──时间线关联(青水之战)──▶ 卡片` 的线。
线的 `label` 是事件标题，方便你认出「这条边是因为哪场仗」。

### 2.3 来源三：正文提及（`mention`）

卡片正文如果写到了别的卡片名/别名，也算一条边（复用自动识别的结果，见 §5）：

```python
for match in autolink.find_mentions(world, card.body, exclude_document_id=document.id)[:40]:
    add_link(document.id, match["document_id"], "mention", match["matched"])
```

**真实例子：** 「石头城」卡片的正文里出现「青水」两字，而「青水」是一张已有卡片，
就产生一条 `石头城 ──正文提及(青水)──▶ 青水` 的线。

## 3. 图谱是怎么算出来的（`world/services/graph.py`）

核心函数是 `build_graph(world, ...)`。它**每次请求都从头算一遍**，而不是读一张预存好的表。
整个过程可以拆成五步：

```text
① 取节点   世界内未删除、非文件夹的文档（可选：只取已发布的）
        │
② 收集连线 三种来源各扫一遍 → add_link() 去重
        │
③ 邻域裁剪 指定了中心节点？用 BFS 只留 depth 跳以内
        │
④ 统计度数 每条边给两端各 +1
        │
⑤ 筛选     hide_isolated 隐藏孤立点 / query 搜索命中 + 一跳邻居
```

### 3.1 第一步：取节点

```python
documents_qs = (
    world.documents.filter(deleted_at__isnull=True)
    .exclude(document_type=DOC_FOLDER)
)
if published_only:
    documents_qs = documents_qs.filter(hidden=False, is_published=True,
                                       document_type__in=SITE_DOC_TYPES)
documents = list(documents_qs.select_related("entity_type")
                 .order_by("document_type", "position", "id")[:limit])
```

- **文件夹不算节点**（它只是容器，不是内容）。
- `published_only=True` 是给只读访客用的：只画已经发布到站点上的文档，
  这样点节点跳转**不会跳到站点上不存在的页面**。
- 最多取 `limit` 个，`limit` 默认 `MAX_NODES = 400`。
- 只保留这次取到的文档，后面所有连线都要求两端都在 `by_id` 里。

### 3.2 第二步：收集连线 + 去重

三种来源都通过同一个 `add_link()` 落进 `links` 列表，它负责三道过滤和一次去重：

```python
def add_link(source_id, target_id, kind, label=""):
    if not source_id or not target_id or source_id == target_id:
        return                                    # ① 丢掉自环与空端点
    if source_id not in by_id or target_id not in by_id:
        return                                    # ② 两端必须都在本次节点集里
    key = (source_id, target_id, kind, label)
    if key in seen_links:
        return                                    # ③ 完全相同的边只留一条
    seen_links.add(key)
    links.append({"source": source_id, "target": target_id, "kind": kind, "label": label})
```

**去重的键是四元组 `(source, target, kind, label)`。** 含义是：

- 同一对卡片之间的**同一类、同一标签**的边只保留一条；
- 但如果两张卡之间既「引用」又「正文提及」，那是两条不同的边，都保留。

> 这里的边是**有向**的（记录 source 和 target），但画图和算度数时会当成**无向**处理
> （两个方向都算作「两端相连」）。

### 3.3 第三步：邻域裁剪（`_neighborhood`）

当你想「以某张卡为中心，只看它附近的几跳」，图谱就不该把整个世界都画出来。
`_neighborhood()` 用 **BFS（广度优先搜索）** 从中心节点向外扩散：

```python
def _neighborhood(links, center, depth) -> set[int]:
    """从中心节点做 BFS，返回 depth 跳以内的节点集合。"""
    adjacency = {}
    for link in links:                            # 先把边表转成邻接表
        adjacency.setdefault(link["source"], set()).add(link["target"])
        adjacency.setdefault(link["target"], set()).add(link["source"])
    keep = {center}
    frontier = deque([(center, 0)])               # 队列里放 (节点, 层数)
    while frontier:
        node, level = frontier.popleft()
        if level >= depth:                        # 够深了就不再往外扩
            continue
        for neighbor in adjacency.get(node, ()):
            if neighbor in keep:                  # 已经收过就跳过，避免重复与死循环
                continue
            keep.add(neighbor)
            frontier.append((neighbor, level + 1))
    return keep
```

> **BFS 为什么合适：** 我们关心的是「**几跳**」——即距离，而不是走某条路。
> BFS 天然按「第 1 跳、第 2 跳…」一层层扩展，正好符合「邻域」的定义。

裁剪完，把不在这批节点上的边、以及不在集合里的节点都丢掉，中心节点始终保留。

### 3.4 第四步：统计度数（degree）

「度数」就是**一个节点连了几条边**。遍历所有边，给两端各加一次：

```python
degree = {}
for link in links:
    degree[link["source"]] = degree.get(link["source"], 0) + 1
    degree[link["target"]] = degree.get(link["target"], 0) + 1
```

度数会写进每个节点的 payload（`_node_payload`），前端据此决定节点多大——
**连得越多的卡片，在图里越「重」、越显眼**。

### 3.5 第五步：筛选

| 参数 | 效果 |
| --- | --- |
| `hide_isolated=1` | 去掉 `degree == 0` 的孤立节点，并同步丢掉挂在它们身上的边 |
| `query=q` | 保留「名字或类型名包含关键词」的节点，**再加上它们的一跳邻居** |
| `center=<id>&depth=N` | 只看某张卡 N 跳以内的邻域（第三步） |

`query` 的实现要点：先算出命中集合 `hit`，再补上一跳邻居，
这样你搜一个词，既看到命中的卡，也看到「和它直接相连的卡」，不至于孤零零：

```python
hit = {n["id"] for n in nodes if query_lower in n["name"].casefold()
       or query_lower in (n["entity_type_name"] or "").casefold()}
for link in links:                    # 命中节点 + 它们的一跳邻居
    if link["source"] in hit: hit.add(link["target"])
    if link["target"] in hit: hit.add(link["source"])
```

最后返回的结构：

```python
return {
    "nodes": nodes,
    "links": links,
    "center": center,
    "stats": {"documents": …, "links": …, "total_documents": …, "isolated": …},
    "kinds": {"reference": "引用", "event": "时间线关联", "mention": "正文提及"},
}
```

`total_documents` 用的是**和节点同一套筛选**的分母，避免出现
「显示 13 / 14 份文档」这种让人以为少画了一个的错觉。

### 3.6 为什么要设上限：`MAX_NODES` 与 `MAX_MENTION_SCAN`

因为图谱是**即时算的**，节点一多，扫描成本会快速上升。两个常量用来兜底：

| 常量 | 值 | 作用 |
| --- | --- | --- |
| `MAX_NODES` | 400 | 一次最多画 400 个节点；也是接口 `limit` 的上限 |
| `MAX_MENTION_SCAN` | 120 | 「正文提及」只扫前 120 张卡片 |

正文提及尤其贵——它要对每张卡跑一次名字识别（`find_mentions`），
而识别本身还要遍历所有候选名字。所以：

```python
scans = [d for d in documents if d.document_type == DOC_CARD][:MAX_MENTION_SCAN]
...
for match in autolink.find_mentions(world, card.body, exclude_document_id=document.id)[:40]:
```

- 最多扫 120 张卡（`MAX_MENTION_SCAN`）；
- **每张卡最多取 40 条提及**（`[:40]`），防止一张超长文把边表撑爆。

### 3.7 为什么图谱不落库

**节点和连线都不存数据库。** 每次请求即时算，数据库里只存「钉住了哪些节点」
这种视图状态（放在 `Document.settings` 里，前端复用文档的设置接口）。

好处：

- **永远和数据一致。** 你改了卡片属性、加了事件关联，下一次请求图谱就是新的，
  不会出现「改了卡片但图谱还是旧的」。
- 少维护一套「什么时候该重建图谱」的同步逻辑。

代价：

- 每次要重算，所以需要上面那些上限兜住性能。

> 取舍一句话：**用「每次多算一点」换「永远不脏」。** 对一个人写设定的数据量，
> 这笔账很划算。

## 4. 度数如何决定节点权重

度数（`degree`）是图谱里最直接的「重要程度」信号：

| 度数 | 在图里的样子 | 代表含义 |
| --- | --- | --- |
| 0 | 孤立点（可被 `hide_isolated` 隐藏） | 还没和任何东西产生关系 |
| 1~2 | 小节点 | 只挂在一条关系上 |
| 高 | 大节点 | 枢纽：很多卡都指向它 / 它指向很多卡 |

前端拿 `degree` 去设节点半径或字号。所以「临江国」如果被一堆省份引用、
又出现在好几场战役事件里，它自然就会变成图上最大最显眼的那个点。

配套地，`suggestions()` 专门挑**孤立卡片**（度数 0）出来，用在空状态里：

```python
def suggestions(world, limit=8):
    """孤立卡片：还没有任何连线的卡片，建议去连一下（空状态用）。"""
    graph = build_graph(world)
    return [n for n in graph["nodes"] if n["degree"] == 0][:limit]
```

## 5. 名字自动识别（`world/services/autolink.py`）

目标：在卡片正文里找出**已经存在的卡片名 / 别名**，前端据此把它渲染成链接。
这和 §2.3 的「正文提及」连线用的是同一套逻辑。

### 5.1 为什么中文不能按空格分词

英文句子有空格，切词比较容易：

```text
"The Battle of Green River was fought in 1850."
→ ["The", "Battle", "of", "Green", "River", ...]
```

中文是一串连写的汉字：

```text
"青水之战爆发于临江国的北境"
```

这里没有空格，**没法用「按空格切」的办法切出词**。而且中文里还有大量
「歧义切分」的情况（「乒乓球拍卖完了」到底是「乒乓球/拍卖」还是「乒乓球拍/卖」）。

所以这里换一个**不靠分词器**的思路：**我手里已经有一份「名字名单」**
（所有卡片的 `mention_names()` = 主名 + 别名），
要做的事变成——**拿名单去正文里做「子串匹配」**，看哪些名字出现了。

```python
def mention_names(self) -> list[str]:
    """能被自动识别成这张卡的名字：主名 + 别名"""
    names = [self.document.name]
    names += [str(a) for a in (self.aliases or []) if str(a).strip()]
    return [n for n in names if n and n.strip()]
```

### 5.2 三条策略：最长匹配优先 + 不重叠 + 跳过链接

候选名字先按**长度从长到短**排序：

```python
pairs.sort(key=lambda item: len(item[0]), reverse=True)
```

然后在正文里逐个名字查找出现的每一次：

```python
for name, document in _candidates(world, exclude_document_id):
    start = text.find(name)
    while start >= 0:
        end = _match_span(text, name, start)
        if not _overlaps(start, end, spans) and not _overlaps(start, end, taken):
            taken.append((start, end))
            matches.append({...})
        start = text.find(name, end)          # 从本段末尾继续找下一次
```

三条策略合起来的意思是：

| 策略 | 做法 | 为什么 |
| --- | --- | --- |
| **最长匹配优先** | 名字按长度倒序试 | 若同时有「亚历山大」和「亚历山大图书馆」，先试长的才能整段认出来，而不是只认出前半截 |
| **不重叠** | 命中区间不能和已命中的 `taken` 相交 | 一处文字只链一次；短名让位给已经占住位置的长名 |
| **跳过链接区间** | 命中区间不能落在已有的 `[[名字]]` 里 | 已经是链接的地方不再重复识别 |

`taken` 记录本次识别已经「占用」的区间；`spans`（`_linked_spans`）记录正文里
**本来就存在的 `[[名字]]` 链接**区间：

```python
_LINK_SPAN = re.compile(r"\[\[([^\]\n]{1,80})\]\]")
```

> 类比：像在一段话上贴荧光贴纸。长词先贴，贴过的地方（`taken`）
> 和已经画了链接的地方（`spans`）就不许再贴。

相关上限：单个名字最长 `MAX_NAME = 60`（避免把整段话当名字）；
一次识别最多 `MAX_MATCHES = 300` 条命中（防长文拖慢接口）。

### 5.3 复数 / 所有格吞并

英文里，卡片叫 `Harrowdeep`，正文写 `Harrowdeeps`（复数）或 `Harrowdeep's`（所有格），
也应该算命中。所以命中时会**往后多吃一个后缀**：

```python
_PLURAL_TAILS = ("'s", "’s", "s", "es")

def _match_span(text, name, start) -> int:
    end = start + len(name)
    tail = text[end:end + 2]
    for candidate in _PLURAL_TAILS:
        if tail.startswith(candidate) and (candidate != "s" or not name.endswith("s")):
            return end + len(candidate)      # 连同后缀一起算进命中区间
    return end
```

有个细节：名字本身以 `s` 结尾（如 `Harrowdeeps`）时，不会再额外吞一个 `s`，
避免把 `Harrowdeepsss` 这种拼写也误判成命中。

### 5.4 模糊匹配：Levenshtein 编辑距离

人打英文名字常常打错一两个字母：`Harrowdeep` 打成 `Harrowdeap`。
`fuzzy_candidates()` 用**编辑距离**容忍这种小错误。

**编辑距离（Levenshtein distance）** 指「把 A 改成 B，最少要几步」
（插入 / 删除 / 替换各算一步）。例如：

| A | B | 距离 | 说明 |
| --- | --- | --- | --- |
| `harrowdeep` | `harrowdeep` | 0 | 一模一样 |
| `harrowdeep` | `harrowdeap` | 1 | 替换 1 个字母 |
| `harrowdeep` | `harrowdep` | 1 | 删掉 1 个字母 |

实现是**带上限、可提前退出**的：

```python
def _edits_within(a, b, limit) -> bool:
    if abs(len(a) - len(b)) > limit:
        return False                 # 长度差太大，直接不可能
    ...
        if best > limit:
            return False             # 这一行最好的结果都超限，后面不用算了
    return previous[-1] <= limit
```

两个关键常量：

```python
FUZZY_MIN_LENGTH = 5      # 太短（≤4）的名字不做模糊匹配
FUZZY_MAX_DISTANCE = 2    # 编辑距离最多容忍 2 步
```

而且**只对拉丁词做**（`^[A-Za-z]` 开头），中文名字不参与模糊匹配：

```python
if not re.match(r"^[A-Za-z]", name):
    continue                       # 中文名字不做模糊匹配（误报太多）
```

**为什么短词不做模糊匹配？** 假设有张卡叫 `Mo`（2 个字母），
距离限制是 2，那么 `go`、`no`、`so`、`do`、`me`、`my` 全都在距离 2 以内，
正文里随便一个两字母词都会被链成这张卡，噪到没法用。名字越长，
「恰好落在距离 2 以内」的无关词就越少，模糊匹配才有意义。

> 一句话：**模糊匹配是把双刃剑**——设了长度门槛（≥5）和距离上限（≤2），
> 才能「容忍手滑」又「不误伤」。

## 6. `detect_new_names`：发现「该建卡但还没建」的名字

图谱和识别都是围绕「已有卡片」转的。但写作时常常是反过来：
**你先在正文里反复提到一个名字，卡片还没建。**
`detect_new_names()` 就负责把这些名字揪出来，作为「创建为卡片」的候选。

它只做一个**保守的启发式**：

```python
known = {name.casefold() for name, _doc in _candidates(world, exclude_document_id)}
counter = {}
for raw in re.findall(r"[\u4e00-\u9fff]{2,6}|[A-Z][a-z]{2,15}", text or ""):
    key = raw.casefold()
    if key in known:
        continue                          # 已经是卡片名字，跳过
    if raw[0] in CJK_STOP_HEADS or raw[-1] in CJK_STOP_TAILS:
        continue                          # 「的洞室」这种碎片不算名字
    counter[raw] = counter.get(raw, 0) + 1
ranked = sorted(counter.items(), key=lambda kv: (-kv[1], kv[0]))
return [name for name, count in ranked if count >= 2][:20]
```

规则拆开看：

| 步骤 | 做法 | 目的 |
| --- | --- | --- |
| 切候选 | 正则 `[\u4e00-\u9fff]{2,6}`（2~6 个汉字）或 `[A-Z][a-z]{2,15}`（首字母大写的英文词） | 圈出「像名字」的片段 |
| 排除已知 | 已经在名单里的跳过 | 只找「还不是卡片」的名字 |
| 过滤虚词 | 首字在 `CJK_STOP_HEADS` 或尾字在 `CJK_STOP_TAILS` 的跳过 | 剔除被切碎的短语 |
| 计数 | 统计每个候选出现次数 | 出现多的更可能是真名字 |
| 取前 20 | 出现 **≥2 次**，按次数降序取前 20 | 只留「反复出现」的，噪声更少 |

### 6.1 中文虚词过滤（`CJK_STOP_HEADS` / `CJK_STOP_TAILS`）

中文里「的、了、在、和、与…」这些助词/虚词粘得很紧。正则一滑，
很容易切出「**的**洞室」「大**的**门」这类**首尾是虚词的碎片**。
这些显然不是名字，所以用两组字符集在**首/尾**挡掉：

```python
CJK_STOP_HEADS = set("的了在和与是有把被就都也这那很更最又还只从对向以为上下中前后内外之而其")
CJK_STOP_TAILS = set("的了着过和与是在有被把就都也这那之其而且并以及")

if raw[0] in CJK_STOP_HEADS or raw[-1] in CJK_STOP_TAILS:
    continue                          # 「的洞室」这种碎片不算名字
```

> 注意只在**开头和结尾**判断，不查中间。因为正常的名字里也可能带虚词字
> （比如「和之国」的「和」在开头…这属于会漏掉一点点的取舍），
> 但边界判断已经能挡掉绝大多数碎片，且**误杀很少**。

这个函数被「值得添加」（`suggestions` 接口）复用，
界面上汇总成全库范围的「反复出现但还没有卡片的名字」候选列表。

## 7. 反向链接与搜索

图谱「向外看」（我连到谁），**反向链接**则是「向内看」（谁提到我）。

### 7.1 反向链接（`backlinks`）

接口：`GET /api/world/backlinks/<doc_id>`。
规则：**按名字 / 别名在别人的标题或正文里出现来算**。

```python
names = [document.name] + list((card.aliases if card is not None else []) or [])
for other in Document.objects.filter(world=world, deleted_at__isnull=True).exclude(pk=document.pk):
    ...
    haystack = f"{other.name}\n{body}"                    # 标题 + 正文
    matched = next((name for name in names if name and name in haystack), "")
    if not matched:
        continue
    found.append({"id": other.id, "name": other.name, "type": other.document_type,
                  "matched": matched, "snippet": …})
```

返回 `{mentions: [...], count: N}`。每一条都带 `matched`（命中的是主名还是哪个别名）
和一段 `snippet`（命中位置前后的上下文）。`snippet` 还会把正文里的换行替换成空格，
方便直接显示成一行。

> 注意：反向链接和自动识别是**两套独立实现**。反向链接为了简单，用的是
> 朴素的「子串在内」判断（`name in haystack`），不做最长匹配 / 不重叠那套精细处理；
> 而正文提及连线（§2.3）走的是完整的 `find_mentions`。

### 7.2 搜索（`search`）

接口：`GET /api/world/search?q=…`（工作区的 ⌘K 搜索面板用它）。
它是一个**全库子串搜索**，把每份文档拼成一个「haystack」再找关键词：

```python
haystack_parts = [document.name]                 # 标题
card = getattr(document, "card", None)
if card is not None:
    haystack_parts.extend(card.aliases or [])    # 别名
    haystack_parts.append(card.body or "")       # 正文
    for value in (card.values or {}).values():   # 属性值（只取标量）
        if isinstance(value, (str, int, float)):
            haystack_parts.append(str(value))
haystack = "\n".join(part for part in haystack_parts if part)
position = haystack.lower().find(lowered)         # 大小写不敏感
```

- 命中后截取关键词前后一段做 `snippet`（前面 30 字 + 关键词 + 后面 40 字）。
- 结果**按最近改动排序**（`order_by("-updated_at", "-id")`），新的在前。
- 结果条数由 `limit` 控制（默认 20，最大 100）。
- 加 `?fuzzy=1` 时，还会用 §5.4 的模糊匹配补几条「你是不是想找…」的建议。

```python
if request.GET.get("fuzzy") in ("1", "true", "yes"):
    for match in autolink.fuzzy_candidates(world, keyword, limit=6):
        …  # 拼成 "≈ 你是不是想找「…」"
```

## 8. 相关接口清单

都挂在 `/api/world/` 下（路径结尾不带斜杠），定义见 `world/urls.py`：

| 方法 | 路径 | 视图 | 作用 |
| --- | --- | --- | --- |
| GET | `/api/world/graph` | `graph_view` | 世界图谱：节点 + 连线。参数 `q` / `hide_isolated=1` / `center=<id>&depth=1..3` / `limit` |
| POST | `/api/world/autolink` | `autolink_view` | 正文名字识别：返回命中的卡片与位置（`text`、可选 `exclude`） |
| GET | `/api/world/search` | `search` | 全库搜索：标题/别名/正文/属性值；`q`、`limit`、`fuzzy=1` |
| GET | `/api/world/backlinks/<doc_id>` | `backlinks` | 谁提到了这张卡（按名字/别名在正文与标题里出现来算） |
| GET | `/api/world/suggestions` | `suggestions` | 「值得添加」：重复出现的新名字 / 空壳卡片 / 没人引用的文档 / 未关联事件 |

`graph_view` 的两个默认行为值得记住：

- **默认把世界里所有文档都画出来**（含孤立节点）——图谱是「世界的地图」，
  不该只显示已经连起来的那些。
- **只读访客只会拿到已发布的节点**（`published_only = not can_edit`），
  这样点节点跳转不会跳到站点上不存在的页面。

另外，`suggestions` 受世界设置里的「AI 功能」开关（`world.ai_enabled`）联动：
关掉时直接返回空建议，**不会偷偷在后台再算一遍**。
