# WorldConcept 编辑器交互方案（统一卡片编辑器外壳）

日期：2026-10-27
状态：已采纳（2026-10-27，方向修正：复用卡片编辑器外壳）
范围：`/w/<slug>/wiki/edit` 的写作、引用、发布、冲突与评论体验（不含公开读页改版）
视觉基准：[world-concept-editor.html](../../.design/current/world-concept-editor.html)

## 1. 核心方向

WorldConcept 不再维护第二种编辑器，而是「卡片编辑器 + 世界概念的发布语义」。

- 使用与 `CardEditor.tsx` 完全相同的 `<section className="panel editor">` 外壳。
- 复用同一套头部、正文、底部保存栏、斜杠菜单、选区浮条、拖拽手柄、右键菜单、评论与媒体库。
- 不新增独立顶部操作栏、固定格式工具栏、右侧目录/词条栏、起步面板、独立预览覆盖层。

WorldConcept 只保留三处必要差异：

1. `editor-kicker` 的类型 chip 为「概念」，并多一个发布状态 chip（`已发布` / `草稿`）。
2. `editor-actions` 在「封面 / 评论 / 保存」之后增加「发布」；空正文时禁用。
3. `save-bar` 右侧显示发布状态（`公开：已发布` / `公开：否`）。

## 2. 目标与非目标

**目标**

- 用户从普通卡片切到世界概念时，不需要学习第二套编辑器。
- 写作、引用、评论、插图全部沿用已有交互。
- 发布状态清楚；空正文不能发布；409 冲突不丢本地稿。

**非目标**

- 独立编辑器框架（头部、工具栏、右栏、底部发布条）。
- 起步模板或按卡片自动生成章节。
- AI 生成正文、多人实时协作、多草稿分支。
- 概念独立媒体库、公开读页信息架构改版。

## 3. 外壳对齐

以 `CardEditor.tsx` 为唯一参照，WorldConcept 逐项对齐：

| 位置 | 卡片编辑器 | WorldConcept |
| --- | --- | --- |
| 外壳 | `section.panel.editor` | 相同 |
| 封面 | `div.page-cover`（可选） | 相同，可后补 |
| 图标 | `button.page-icon` | 相同 |
| 类型区 | `editor-kicker` + `.chip` + slug | `概念` chip + 发布状态 chip + slug |
| 标题 | `input.title-input` | 相同，占位「未命名卡片」 |
| 元信息 | `editor-meta`：修订 / 字数 / 保存状态 | 相同，不新增状态词 |
| 操作 | `editor-actions`：封面 / 评论 / 保存 | 追加「发布」主按钮 |
| 正文 | `editor-body` + Tiptap | 相同 |
| 编辑交互 | `/` 斜杠、选区浮条、拖动手柄、右键菜单 | 相同 |
| 提及 | `@` mention、正文卡片名自动链接 | 相同 |
| 评论 | `CommentsPanel` + 选区锚点 | 相同 |
| 媒体 | `MediaLibraryDialog` | 相同 |
| 底栏 | `save-bar` + 公开状态 | 相同，显示发布状态 |

明确移除：`.concept-editor-head`、`.concept-toolbar`、`.concept-layout`、`.concept-outline`、`.concept-preview-overlay`、`ConceptStartPanel`、`ConceptRail`。

## 4. 关键流程

### 4.1 空草稿

- 与卡片编辑器一致：正文区显示空段落占位「从这里开始写。输入 / 打开插入菜单。」
- 不出现起步面板，不插入模板章节。
- 标题为空时使用「未命名卡片」占位；发布按钮置灰。

### 4.2 常规写作

- 保留 850ms 防抖自动保存与 `⌘/Ctrl+S` 立即保存。
- 状态只在 `editor-meta` 显示：`修订 rN`、`N 字`、`已保存 HH:MM`（或 `自动保存…` / `保存失败`）。
- 格式操作通过选区浮条、斜杠菜单和右键菜单完成，不增加固定工具栏。
- `@` mention 自动补全与正文卡片名自动链接保持现状。

### 4.3 引用世界素材

- 通过 `@` 或斜杠菜单「嵌入卡片 / 提及」引用，不再提供右栏词条列表。
- 不做「未引用 / 已引用」统计面板；如后续需要，放进发布确认的提示信息，而不是常驻栏。

### 4.4 发布

按钮状态：

| 状态 | 按钮 | 行为 |
| --- | --- | --- |
| 正文为空 | 发布（禁用） | 说明先写正文 |
| 有草稿内容 | 发布 | 打开发布确认 |
| 保存中 / 冲突未解决 | 发布（禁用） | 等待保存或先处理冲突 |

发布确认（轻量弹层，不阻断写作）：

- 标题：「发布世界概念」。
- 摘要：正文字数与修订号、引用的公开卡片数、未解决评论数。
- 动作：取消、发布；发布成功后 `editor-kicker` 的状态 chip 变为「已发布」，`save-bar` 同步更新。
- 不做独立的全屏发布检查页；空正文是唯一阻断项。

### 4.5 状态

- 保存状态继续使用卡片编辑器的文案，不引入 `ConceptStatus` 组件。
- 发布状态只出现在两个位置：`editor-kicker` 的状态 chip、`save-bar` 右侧。
- 不显示「草稿 · 未保存」这类需要用户判断的中间态。

### 4.6 冲突（409）

- 暂停自动保存，本地内容保留可继续编辑。
- 在 `editor-body` 顶部显示一条与 `.editor-error` 同款的行内提示：

```
草稿已在别处更新，自动保存已暂停。
[载入最新草稿]  [复制我的正文]
```

- 「载入最新草稿」二次确认并说明将丢失的本地修改；「复制我的正文」写入剪贴板。
- 不做后端覆盖接口（S1 不提供「强制覆盖」）。

### 4.7 评论

- 完全复用卡片编辑器：选中文本 → 浮条「评论」→ `CommentsPanel` 预填 quote 与锚点。
- 解决后不删除锚点 mark，与卡片行为一致。

### 4.8 媒体

- S1 继续使用 `MediaLibraryDialog`。
- S2 再评估拖拽/粘贴上传，不改变编辑器外壳。

### 4.9 历史

- 保留 `ConceptHistoryDialog`。
- 入口改为 `editor-actions` 末尾的图标按钮（与卡片编辑器按钮同款），不占用头部位置。
- 若 S1 暂不做入口，API 保留，S2 补按钮。

### 4.10 只读与权限

- 直接使用卡片编辑器的 `readOnly` 行为：正文只读、隐藏封面/评论/保存/发布。
- `save-bar` 显示「只读视图 · 登录后可编辑」。
- 公开页入口继续由工作区顶栏提供。

### 4.11 移动端

- 与工作区其他卡片编辑器一致：顶栏显示菜单按钮，`editor-actions` 自动换行。
- 不提供工具栏横向滚动、素材抽屉或底部固定发布条。
- 375px 下需保证操作按钮换行后不被裁切。

## 5. 实现方式

推荐先抽取再接入，避免复制一份新外壳：

1. 从 `CardEditor.tsx` 抽出呈现层 `EditorShell`（`page-icon` / `editor-kicker` / `title-input` / `editor-meta` / `editor-actions` / `editor-body` / `save-bar` 的插槽）。
2. `CardEditor` 与 `ConceptEditor` 分别作为容器接入，保留各自的保存、发布、冲突逻辑。
3. 删除 `ConceptEditor` 中的 `concept-editor-head`、`concept-toolbar`、`concept-layout`、`concept-outline`、预览覆盖层与模板按钮。
4. 清理 `world-concept.css` 中仅服务于旧编辑器的样式；公开读页样式保留。
5. 不改变后端接口与数据模型。

## 6. 数据与接口

全部复用，不新增：

- `GET /api/worlds/<slug>/`：`cards`、`can_edit`、`is_public_read`
- `GET/PATCH /api/worlds/<slug>/concept/`：草稿保存（带 `updated_at` 冲突检测）
- `POST /api/worlds/<slug>/concept/publish/`
- `GET /concept/revisions/` 与恢复接口
- `GET/POST /concept/comments/`
- 世界媒体库接口

前端新增仅为：发布状态映射、发布确认弹层、冲突行内提示。

## 7. 分阶段

### S1：外壳统一与发布闭环

- 抽取 `EditorShell` 并接入概念编辑器。
- 移除旧头部、工具栏、右栏、起步面板、独立预览。
- 发布按钮、发布确认、空正文禁用、发布状态 chip。
- 保留自动保存、409 暂停与历史 API。

验收：

- 概念编辑器与卡片编辑器的 DOM 结构、类名、间距一致（逐项对比）。
- 空正文无法发布；发布后状态 chip 与 `save-bar` 同步。
- 1440 / 1000 / 375 无横向溢出，控制台无错误。
- 普通卡片编辑器无回归。

### S2：就地反馈

- 冲突行内提示与「载入最新 / 复制正文」。
- 评论入口与未解决数量。
- 历史图标按钮。
- 移动端操作按钮换行检查。

### S3：发布后确认

- 发布成功提示「已发布到搜索与 RSS」。
- 卡片详情页「在世界概念中提到」反向入口。

## 8. 风险与取舍

| 风险 | 取舍 |
| --- | --- |
| 抽取外壳影响卡片编辑器 | 先做结构与样式对齐，逐项截图对比；ConceptEditor 只做接入 |
| 失去目录/词条/预览 | 接受；引用改用 `@` 与斜杠菜单，发布前看效果走公开页 |
| 发布确认过于简单 | 只阻断空正文；其他规则后续追加，不恢复独立检查页 |
| 历史入口被弱化 | 用同款图标按钮保留，API 不动 |
| 移动端操作行拥挤 | 允许换行并右对齐，不新增底部条 |
