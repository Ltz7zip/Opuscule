# P0.2：身份、成员权限与安全写接口

- Date: 2026-10-20
- Status: P0.2 completed (with documented gaps)
- Predecessor: `docs/plans/20261020-p0-vertical-slice.md`
- Design ref: `/tmp/opuscule-design-refs/workspace/pages/登录与初始化.html`

## 目标

把 P0.1 的“localhost 开放写接口”换成可上线的第一版安全边界：

1. Django session auth + CSRF；登录/登出/会话 API。
2. `WorldMembership`：owner / editor / viewer。
3. 公开世界可匿名只读；私有世界仅成员可读；写操作仅 owner/editor。
4. 工作区按 `can_edit` 进入只读或可编辑；公开页与登录页接入同一会话。
5. 前端登录页按 `登录与初始化` 参考实现；登录后回到工作区。
6. seed 创建本地 demo 用户与 owner membership。

## 不在本切片

- Postgres / Redis / S3；仍用 SQLite 本地。
- 邀请链接、成员管理 UI、OAuth、邮箱验证。
- 公开站 SSR。
- CollectionPage / CollectionView / Timeline / Hist / 工具宿主。
- 完整 RBAC 矩阵（workspace 级 admin、资产级权限等）。

## 验收

```sh
cd backend
.venv/bin/python manage.py makemigrations
.venv/bin/python manage.py migrate
.venv/bin/python manage.py seed_demo
.venv/bin/python manage.py test
```

- 匿名 `GET /api/worlds/wuhai/` 可读；匿名 `POST` 卡片 403。
- `traveler` 登录后可创建/修改卡片；非成员 403。
- 私有世界匿名详情 404；成员可读。
- 无 CSRF token 的已登录写请求 403；带 token 成功。
- `/login` 页面可登录，错误有可读提示；登录后工作区可编辑，匿名工作区只读。
- 390 / 1280 页面无横向溢出；控制台无错误。
- 后端测试覆盖登录、CSRF、匿名写、非成员写、私有世界读。

## 风险

- session + Vite proxy 的 CSRF cookie 已在 127.0.0.1:5173 实测；部署域名必须替换 `CSRF_TRUSTED_ORIGINS`。
- `WorldMembership` 迁移给现有 world 没有 owner：seed/测试补；生产迁移要单独处理。
- 本地 demo 密码只能用于 localhost；不能写进生产配置。
- 只读工作区仍会暴露公开世界内容；私有世界在 API 层拦截，不靠前端隐藏。
