# P0.3：个人主页 /u/<username>

- Date: 2026-10-20
- Status: P0.3 completed (with documented P0.4 gaps)
- Predecessor: `docs/plans/20261020-p0.2-auth-permissions.md`
- Design ref: 旧站 `apps/world/models/profile.py`、`views/personal.py`、`templates/profile.html`
- Design doc: §6.1.1

## 为什么补

旧站已经有 `UserProfile` 与 `/u/<username>`：跨世界的作者门面，展示公开世界、精选世界、最近公开卡片与外部链接。
新设计稿漏了它；如果不补，P3 parity 会缺一个真实产品面，也会让“公开站”只剩世界页。

## 目标

1. `UserProfile`：显示名、一句话简介、简介、所在地、网站、链接、置顶世界、公开开关。
2. 公开 API / 页面：`/api/u/<username>/`、`/u/<username>`。
3. 本人编辑：PATCH `/api/profile/`；资料、置顶、公开开关。
4. 可见性：公开主页只投影公开世界/公开卡片；私有主页对他人 404；置顶私有世界 ID 不泄漏。
5. 与 Collection 正交：作者页不塞进 Collection 树；设计稿明确 `/u/<username>` 是世界之外的作者面。

## 不在本切片（P0.4 parity）

- 旧 `blocks` 拖拽排版、`layout` 单/双栏、`accent` 主题色编辑器。
- 自定义 note 区块、题材标签、最近动态（以公开卡片替代）。
- 链接编辑器（P0.3 先展示 seed 链接；PATCH 支持 links，UI 暂不编辑）。
- 头像上传；仍用显示名首字母。
- 关注/粉丝、个人主页评论。

## 验收

```sh
cd backend
.venv/bin/python manage.py test          # 15 tests
.venv/bin/python manage.py check
cd ../frontend
npm run build
```

- 匿名 `GET /api/u/traveler/` 200；只含公开 world/card；`is_owner=false`。
- 匿名 `GET /api/profile/` 403；本人 GET/PATCH 200。
- `is_public=false` 的 profile 匿名 404；本人 200。
- 恶意 `javascript:` link 被清空；裸域名补 https。
- 浏览器 `/u/traveler`：资料、精选世界、最近公开卡片、全部世界；本人可编辑并保存；390/1280 无横向溢出。
- 登录后 Topbar 用户名可进入个人主页。

## 风险

- 个人主页是公开面；必须过滤 private world/private card，不能靠前端隐藏。
- 旧 blocks/layout/accent 未重建，必须在 parity matrix 记录 P0.4，不得宣称完整个人主页 parity。
- 默认 seed profile 只用于本地 demo；生产资料由用户填写。
