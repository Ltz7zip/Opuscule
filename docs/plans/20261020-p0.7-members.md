- Design doc: §4.6 / §6.1

## 目标

owner 能管理已有账号的世界成员，而不是只能靠 seed/ORM：

1. 列出成员（owner/editor/viewer）。
2. 按已注册用户名添加成员，设为 editor 或 viewer。
3. 修改 editor/viewer 角色。
4. 移除成员；owner 不能在这里被移除/降级。
5. editor/viewer 不能管理成员；editor 仍可编辑内容。

## 交付

- `GET /api/worlds/<slug>/members/`（owner）。
- `POST /api/worlds/<slug>/members/`（owner，username + role）。
- `PATCH /api/worlds/<slug>/members/<id>/`（owner，改 role）。
- `DELETE /api/worlds/<slug>/members/<id>/`（owner，非 owner）。
- `WorldMemberSerializer`：display_name/username/role/created_at。
- 前端 `WorldMembersDialog`：成员列表、添加、改角色、移除、错误/空态。
- Sidebar owner 成员按钮；editor/viewer 不显示管理入口。
- 390/1280 适配；dialog 宽 350（390）。

## 不在本切片

- 邀请链接/邮箱邀请/未注册用户。
- 所有权转移、owner 降级、多个 owner。
- 成员审计日志、通知、批量导入。
- 成员权限细粒度（editor 是否能管理 Collection/卡片设置）。
