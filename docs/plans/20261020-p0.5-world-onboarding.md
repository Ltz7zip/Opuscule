# P0.5：世界创建与注册后 onboarding

- Date: 2026-10-20
- Status: P0.5 completed (with documented follow-ups)
- Predecessor: `docs/plans/20261020-p0.4-modules-wiki-explore-register.md`
- Design doc: §4.6 / §6.1

## 目标

注册后不能停在“没有世界”的空白页。让新用户：

1. `/register` 成功 → `/worlds/new`
2. 填世界名/简介/是否公开 → 创建
3. 自动成为 owner，得到 3 个 Collection + 1 张世界概览卡
4. 直接进入 `/w/<slug>` 编辑
5. owner 可在工作区把世界公开到 `/explore`

## 交付

- 后端 `POST /api/worlds/`：登录创建；owner membership；默认 Collection/概览卡；事务。
- 后端 `PATCH /api/worlds/<slug>/`：owner 改 name/description/is_public_read；发布时写 `published_at`。
- 前端 `/worlds/new` lazy 页面：登录 gate、表单、公开开关、错误态。
- 注册成功跳 `/worlds/new`。
- 探索/个人主页增加“新建世界”入口。
- 工作区 owner 顶部“公开 Wiki/取消公开”按钮。
- 测试：匿名拒绝、bootstrap、owner/editor 权限、发布后 explore。

## 验收

cd backend

- 创建成功 201，返回 detail；3 个 Collection + overview card。
- owner 可 PATCH 发布；editor 403；匿名创建 401/403。
- 浏览器创建 → `/w/...` → 发布 → explore/wiki 可读。
- 390/1280 创建页无横向溢出。

## 不在本切片

- 世界设置 UI（名称/简介编辑）、删除、切换器、封面。
- 7 个私人世界上限、配额/邀请/成员管理。
- 自定义 slug；中文名当前用 `world` / `world-2` fallback。
- 世界创建向导（模板、示例数据、导入）。
- 注册邮箱验证/限流。

## 风险

- 公开开关是 owner-only；editor 不应能发布，测试覆盖。
- 创建事务必须原子；否则会出现没有 owner 的世界。
- 创建后默认私有；用户可在工作区公开，避免误公开。
- 当前没有世界数量限制，生产前必须加配额。
