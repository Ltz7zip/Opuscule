# P0.9：所有权转移与世界软删除

- Date: 2026-10-20
- Status: P0.9 completed (audit/purge deferred)
- Predecessor: `docs/plans/20261020-p0.8-invites.md`
- Design doc: §4.6 / §6.1
- ADR: ADR-0016

## 目标

1. owner 可以把世界所有权转移给现有成员；转移后自己变 editor。
2. owner 可以软删除世界；世界从列表/探索/Wiki 消失，邀请失效。
3. owner 可以在回收站恢复；恢复后世界重新可用。
4. 非 owner 不能转移/删除/恢复。
5. 删除不物理清除内容，避免误删不可逆。

## 交付

- `POST /api/worlds/<slug>/transfer-ownership/`：owner → 现有成员；事务；旧 owner 降 editor。
- `DELETE /api/worlds/<slug>/`：软删 `deleted_at`；撤销未用邀请。
- `GET /api/worlds/trash/`：owner 的已删除世界。
- `POST /api/worlds/<slug>/restore/`：owner 恢复；同名活动世界冲突 400。
- `World` 默认 manager 过滤 deleted；`all_objects` 用于回收站/恢复。
- 前端 MembersDialog「转移所有权」；WorldSettingsDialog danger zone「删除世界」；`/trash` 页面恢复。
- 个人主页 owner 增加回收站入口。
- 测试：transfer、delete/restore 隐藏/恢复、owner-only。

## 验收

```sh
cd backend
.venv/bin/python manage.py test          # 32 tests
cd ../frontend
npm run build
```

- 删除测试世界 → `/u/<owner>`；`/trash` 列出；恢复 → `/w/<slug>`。
- 删除后 `/api/worlds/<slug>/` 404；列表/探索不含；邀请 info valid=false。
- 转移后目标 owner、原 owner editor；原 owner 再转移 403。
- 390/1280 dialog / trash 无横向溢出。

## 不在本切片

- 物理清除/保留期限/回收站配额。
- 所有权转移审计、通知、二次确认输入世界名。
- 已删除世界的成员列表/邀请管理。
- 恢复时的 slug 冲突 UI（当前 API 400）。
- 批量删除/恢复。
