- Predecessor: `docs/plans/20261020-p0.3-personal-profile.md`

## 用户目标

网站至少要有：工作/编辑区、Wiki 浏览、个人主页、登录/注册、探索公开世界；
后续地图、AI、工具页要能继续加，不能把所有逻辑塞进一个页面。公开页打开时不能把
编辑器整套下载/启动，避免风扇持续转。

## 交付

### 1. 页面注册表 + 路由级 lazy

- `frontend/src/app/routes.ts`：`/`、`/explore`、`/u/:username`、`/login`、`/register`、
  `/w/:world/wiki`、`/w/:world/wiki/:slug`、`/w/:world`。
- `frontend/src/app/RouteView.tsx`：所有页面 `React.lazy`；`Workspace` 是唯一 Tiptap chunk。
- `App.tsx` 只负责 session、popstate、logout，不静态 import 页面。
- 未来地图/AI 继续加 route + lazy feature；不改 App 结构。

### 2. 公开 Wiki

- 后端 `GET /api/worlds/<world>/cards/by-slug/<slug>/`；匿名只看 `is_public` 卡片。
- 前端 `/w/:world/wiki`：Collection 导航、搜索、卡片索引。
- `/w/:world/wiki/:slug`：只读文章页；用轻量 `RichText` 递归渲染 Tiptap JSON，不加载 ProseMirror。
- 公开首页/个人主页卡片链接改到 Wiki，不再把公开阅读导进编辑器。

### 3. 探索

- 后端 `GET /api/explore/`：只返回 public-read 世界，附 `description/card_count/collection_count`。
- 前端 `/explore`：公开世界卡片、搜索、进入 Wiki/工作区。
- 公开 Topbar 增加探索入口；首页 hero 增加探索/Wiki 入口。

### 4. 注册

- 后端 `POST /api/auth/register/`：CSRF、用户名 3–32 位、密码 ≥8、创建 User + UserProfile、自动登录。
- 前端 `/register`：登录/注册 tab、错误态、成功跳 `/u/<username>`。
- 开放注册，无邮箱/邀请/限流；这些是后续。

### 5. 性能预算

- 公开首屏 JS ≤120 kB gzip；工作区 editor chunk ≤160 kB gzip；公开页 0 个常驻动画；顶栏去 `backdrop-filter`。
- 当前 production build：入口 72.84 kB gzip；Workspace 130.87 kB gzip；公开 preview 传输 JS 约 77.6 kB，无 editor。
- 后续 P1 加 Lighthouse/CI budget 与真实设备复测。

## 验收

```sh
cd backend
.venv/bin/python manage.py test          # 19 tests
.venv/bin/python manage.py check
cd ../frontend
npm run build
```

- 19 个后端测试通过；explore 只出公开世界；注册/重名/弱密码/CSRF 有覆盖。
- 公开 Wiki 匿名可读；私密卡片/私有世界不出现；无 `.tiptap` DOM。
- 390/1280 下 explore、register、wiki、wiki card、profile 无横向溢出。
- production build 中 public chunk 不含 Tiptap；`Workspace` 仅在工作区加载。

## 非目标 / 后续

- 公开站 SSR、边缘缓存、SEO/RSS；P1。
- 全文搜索、分页、探索筛选器；P1。
- 邀请制/邮箱验证/登录限流/密码重置；P1。
- 世界创建向导；注册后暂时没有自己的世界。
- 地图/AI/时间线只保留模块边界，不在本切片实现。
- Wiki 嵌套 Collection 递归投影、wiki 搜索服务端化。
