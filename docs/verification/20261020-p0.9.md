## 已验证

- 后端 32 tests：owner transfer → 目标 owner / 原 owner editor；原 owner 再转移 403。
- soft delete → `/api/worlds/<slug>/` 404；`/api/worlds/` 不含；`/api/worlds/trash/` 列出；restore 后 200。
- editor 不能 delete；非 owner 不能 restore；delete 撤销 invites。
- 浏览器：创建“软删测试” → 打开世界设置 → 删除（confirm）→ 跳个人主页 → `/trash` 看到“软删测试” → 恢复 → 回到 `/w/world`。
- 测试世界已物理清理；当前库只剩 `wuhai` / `traveler`。
- 390/1280 dialog 与 trash 页面无横向溢出（trash 用同一响应式规则）。
- 控制台 0 错误。

## 明确缺口

- 所有权转移 UI 的入口/选择/确认已在 P0.10 浏览器实际完成一次转移；本切片当时未实测。
- 没有转移/删除审计日志或通知；删除确认只弹 confirm，未要求输入世界名。
- 没有物理清除/保留期限；回收站没有配额；没有恢复冲突的 UI 提示。
- 删除后成员/邀请的管理入口不可达（符合预期），但没有专门的“已删除世界详情”。
- 无前端 E2E；无 git commit。

## 结论

- 置信度：**B**。删除/恢复/转移主路径有后端测试，删除/恢复有浏览器证据；转移 UI 的端到端点击未实测。
- 这是 P0.9 最小治理切片，不是完整删除/合规系统。
