## 1. 地图文档是什么

在 Opuscule 里，**地图和卡片、时间线一样，都是一份「文档」**：
数据库中它是 `apps.documents.models.Document` 里 `document_type = "map"` 的那一类
（常量 `DOC_MAP = "map"`）。它走文档树的同一套规则：有名字、有父子位置、能发布、能回收。

但一张地图文档里其实同时装着**两类完全不同的数据**，理解这一点是理解整个地图模块的钥匙：

| 数据 | 存在哪里 | 谁在用 | 服务端管不管 |
| --- | --- | --- | --- |
| **地图世界本身**（地形、国家网格、风格、图层…） | `Document.map_data`（一整段文本） | 前端地图引擎自己保存/读取 | **完全不管**，只当它是「一个不透明的大字符串」 |
| **标注**（图钉 / 区域 / 文字） | `MapLayer` + `MapMarker` 两张关系表 | 工作区面板、卡片双向桥 | 完整管理 |
| **底图设置**（背景图片、缩放、偏移） | `Document.settings`（JSON） | 前端渲染背景 | 存取一段配置 |

### 1.1 为什么把地图世界存成「一整段文本」

第三方地图生成器（Fantasy Map Generator）有自己的一整套内部状态：
`pack`（地形采样）、`grid`（网格）、`styles`（样式）、`layers`（它自己的图层）……
如果把它拆成一个个数据库字段，一旦上游升级改了结构，我们的代码就会崩。

所以这里做了一个取舍：**地图世界整包原样存进 `Document.map_data`，服务端不解析、不拆字段。**
前端拿到这段文本直接喂给地图引擎的 load，编辑完再把整段 save 回来。

```python
# apps/documents/models/document.py —— Document 上的地图字段
map_data = models.TextField("地图数据", blank=True, default="")
```

> 类比：这就像把一个压缩包塞进抽屉，抽屉本身不需要知道压缩包里装了什么。
> 接口 `/api/world/maps/<id>/data` 的 GET / PUT 就是「取压缩包 / 换压缩包」。

### 1.2 两种脸：工作区面板 与 `/map` 独立页

同一份地图数据，有两个入口：

| 入口 | 地址 | 说明 |
| --- | --- | --- |
| 工作区面板 | `/world` 里内嵌 | 用 iframe 嵌进来，和卡片、时间线并排 |
| 地图独立页 | `/map` → `/map/2d` | 全屏的独立页面，`apps/world/mapdoc.py` 提供 |

独立页有两档视图（`MAP_VIEWS`）：

| 档位 | 地址 | 干什么 |
| --- | --- | --- |
| 平面 | `/map/2d` | 生成 / 编辑 / 图层 / 标注 |
| 地形 | `/map/3d` | 三维地形与地球仪 |

`/map` 本身只做一次 302 跳到默认档（`/map/2d`），免得两个地址各有一份页面。

独立页支持几个查询参数：

| 参数 | 作用 |
| --- | --- |
| `?doc=<id>` | 指名看哪一张地图；不带就挑世界里第一张地图 |
| `?embed=1` | 被工作区面板 / 发布站点用 iframe 嵌进来：去掉外壳留白。**默认只读**，要可编辑得显式给 `readonly=0` |
| `?theme=paper\|light\|dark` | 只读站点里显式指定主题；世界主题是浅色时才默认浅色 |

## 2. 图层：MapLayer

**图层**是一组标注的容器，可以整体显示/隐藏、整体调透明度。模型定义：

```python
class MapLayer(models.Model):
    document = models.ForeignKey(Document, on_delete=models.CASCADE, related_name="map_layers")
    name = models.CharField("名称", max_length=60, default="默认")
    position = models.PositiveIntegerField("排序", default=1)
    visible = models.BooleanField("显示", default=True)
    opacity = models.FloatField("透明度", default=1.0)
```

| 字段 | 类型 | 含义 | 初学者理解 |
| --- | --- | --- | --- |
| `document` | 外键 | 属于哪张地图 | 「这个图层挂在哪张地图上」 |
| `name` | 文本 | 图层名 | 显示在图层面板里的名字 |
| `position` | 整数 | 排序 | 数字小的排前面；决定图层的**前后顺序** |
| `visible` | 布尔 | 是否显示 | 关掉就是「眼睛图标闭上」，该层标注全部隐藏 |
| `opacity` | 浮点 | 不透明度 | `0.0` 全透明 ~ `1.0` 不透明 |

`MapLayer.to_payload()` 额外会带上一个 `marker_count`（这一层里有多少个标注），
前端图层面板用它显示数量。

几条规定：

- **一张地图至少要有 1 个图层。** 如果一张新地图还没有任何图层，
  `map_state()` 会自动建一个叫「默认」的图层，保证前端永远拿得到图层列表。
- **删除时也要留一个。** `map_layer_detail` 的 DELETE 分支会检查：
  只剩 1 个图层时拒绝删除，回 `至少要保留一个图层`。
- **图层的显隐与顺序是「渲染时的事」**，它不改标注本身的数据——
  只是告诉前端「这一层现在要不要画、画在谁前面」。

## 3. 标注：MapMarker

**标注**是地图上真正看得见的东西。一张地图可以有很多标注，每个标注属于某一层。
模型定义（节选）：

```python
class MapMarker(models.Model):
    document = models.ForeignKey(Document, on_delete=models.CASCADE, related_name="map_markers")
    layer = models.ForeignKey(MapLayer, null=True, blank=True, on_delete=models.SET_NULL,
                              related_name="markers")
    kind = models.CharField("类型", max_length=8, choices=MARKER_KINDS, default=MARKER_PIN)
    name = models.CharField("名称", max_length=120, blank=True, default="")
    description = models.TextField("描述", blank=True, default="")
    # 图钉与文字用 x/y（百分比），区域用 points（[[x, y], ...] 百分比多边形）
    x = models.FloatField("x", default=50.0)
    y = models.FloatField("y", default=50.0)
    points = models.JSONField("多边形", default=list, blank=True)
    color = models.CharField("颜色", max_length=16, default="gold")
    icon = models.CharField("图标", max_length=40, blank=True, default="")
    scale = models.FloatField("大小", default=1.0)
    rotation = models.FloatField("旋转", default=0.0)
    # 关联到一张卡片（图钉/区域指向世界里的条目）
    card = models.ForeignKey(Document, null=True, blank=True, on_delete=models.SET_NULL,
                             related_name="marker_links")
    position = models.PositiveIntegerField("排序", default=0)
    created_at = models.DateTimeField("创建于", auto_now_add=True)
```

| 字段 | 含义 |
| --- | --- |
| `document` | 这个标注属于哪张地图文档 |
| `layer` | 挂在哪个图层上（可为空；空则不入层） |
| `kind` | 标注类型：`pin` / `zone` / `label`（见下） |
| `name` | 标注名字 |
| `description` | 描述文字 |
| `x`、`y` | 位置，**百分比坐标**（0~100），不是像素 |
| `points` | 区域用的多边形顶点列表 `[[x, y], ...]`，同样是百分比 |
| `color` | 颜色名（`gold` / `sky` / `violet` / `red` / `teal` / `blue`） |
| `icon` | 图标名 |
| `scale` | 大小倍数（接口里被限制在 `0.2 ~ 4.0`） |
| `rotation` | 旋转角度 |
| `card` | **吸附到的一张卡片**——这是「图钉 ↔ 条目」那座桥的关键 |
| `position` | 同层内的排序 |
| `created_at` | 创建时间 |

### 3.1 三种标注类型的差异

系统里对应三档 `MARKER_KINDS`：

| kind | 界面叫法 | 主要用什么定位 | 典型用途 |
| --- | --- | --- | --- |
| `pin` | 图钉 | `x` / `y`（一个点） | 标一座城、一个地标 |
| `zone` | 区域 | `points`（一个多边形） | 圈一片国土、一块森林 |
| `label` | 文字 | `x` / `y`（一个点） | 只写一段说明文字，不指向卡片 |

> 类比：图钉像地图 App 上的定位大头针；区域像在地图上用马克笔画一个圈；文字标注像贴一张便利贴。

### 3.2 坐标为什么用「百分比」

地图的底图长度可能变、缩放可能变，但 `x = 50, y = 50` 永远表示「正中间」。
把坐标统一成 0~100 的百分比，标注就不会因为换了底图尺寸而全部跑偏。

导入路径里有一个专门的收敛函数：

```python
def _clamp_percent(value) -> float | None:
    """地图坐标一律存 0–100 的百分比；认不出的值当没有。"""
    try:
        number = float(value)
    except (TypeError, ValueError):
        return None
    if not math.isfinite(number):
        return None
    return max(0.0, min(100.0, number))
```

认不出的坐标（空、文字、NaN…）直接当成「没有位置」，而不是硬塞一个 0。

### 3.3 颜色的真源

颜色名到十六进制的映射来自 `models.ERA_COLORS_RGB`，
`map_state()` 会把它算成 `color_hex` 一并发给前端：

| 颜色名 | RGB | 十六进制 |
| --- | --- | --- |
| `gold` | (224, 148, 36) | `#e09424` |
| `sky` | (52, 117, 243) | `#3475f3` |
| `violet` | (82, 81, 193) | `#5251c1` |
| `red` | (236, 58, 58) | `#ec3a3a` |
| `teal` | (26, 176, 121) | `#1ab079` |
| `blue` | (98, 105, 128) | `#626980` |

接口里遇到认不出的颜色，一律回落到第一个（`gold`）。

## 4. 底图与视野

**底图（background）**是垫在地图下面的图片。它不是关系表，而是存进
`Document.settings` 的一段 JSON，形态是：

```json
{
  "background": "https://…/my-map.png",
  "zoom": 1.0,
  "offset_x": 0.0,
  "offset_y": 0.0
}
```

| 键 | 含义 |
| --- | --- |
| `background` | 底图地址（上传文件的 URL 或粘贴的外链） |
| `zoom` | 缩放（也接受旧键名 `bg_zoom`） |
| `offset_x` / `offset_y` | 平移偏移（也接受 `bg_offset_x` / `bg_offset_y`） |

设置底图的接口 `map_background` 支持两种方式：

- **上传文件**（`multipart/form-data`）：走 `file` 字段。
  - 大小上限 25 MB（`MAX_UPLOAD_BYTES`），超了回「图片超过 25 MB，建议先压缩」。
  - 只收 PNG / JPEG / WebP / GIF / AVIF（白名单 `ALLOWED_IMAGE_TYPES`）。
  - 文件存到 `maps/<document.id>/` 目录下。
- **粘贴 URL**：走 JSON 的 `url` 键。
- **清空**：`DELETE` 方法，或 `clear=1`，会把 `background` 键移除。

`map_state()` 在读取时会把背景配置规整成统一结构返回，前端不用关心底层键名。

## 5. 地图实体 ⇄ 卡片：双向桥（`apps/world/services/geo.py`）

这是整个地图模块最有意思的部分。地图引擎里有「国家 / 省份 / 城镇 / 河流」这些**实体**，
工作区里有对应的**卡片**。`geo.py` 负责在两边来回搬：

```
   地图引擎（前端从 pack 抽好的扁平 JSON）
        │
        │  ① import-entities：地图实体 → 卡片 + 图钉
        ▼
   工作区（EntityType + Document/Card + MapMarker）
        │
        │  ② distribute：给一个条目自动铺开下一级
        ▼
   新卡片 + 新图钉（又回到地图上）
```

**方向依赖很干净：`geo.py` 只碰模型与 `normalize`，绝不 import `views`。**
这样桥两边的逻辑可以单独测试，也不会绕成循环依赖。

### 5.1 地理层级与类型

导入之前，系统要先保证「国家 / 省份 / 城镇 / 地点 / 河流 / 山脉 / 道路」这七种
`EntityType` 存在，而且带着该有的属性。这张「级别表」就是层级的地图：

```python
GEO_LEVELS = {
    "国家": {"icon": "flag",     "color": "gold",   "child": "省份", "spread": 12.0},
    "省份": {"icon": "map",      "color": "sky",    "child": "城镇", "spread": 6.0},
    "城镇": {"icon": "building", "color": "teal",   "child": "地点", "spread": 2.5},
    "地点": {"icon": "map-pin",  "color": "violet", "child": "",     "spread": 1.0},
    "河流": {"icon": "waves",    "color": "blue",   "child": "",     "spread": 3.0},
    "山脉": {"icon": "mountain", "color": "violet", "child": "",     "spread": 3.0},
    "道路": {"icon": "route",    "color": "teal",   "child": "",     "spread": 3.0},
}
```

| 级别 | 图标 | 图钉颜色 | 下一级 | 铺开半径（地图百分比） |
| --- | --- | --- | --- | --- |
| 国家 | `flag` | `gold` | 省份 | 12.0 |
| 省份 | `map` | `sky` | 城镇 | 6.0 |
| 城镇 | `building` | `teal` | 地点 | 2.5 |
| 地点 | `map-pin` | `violet` | —（末级） | 1.0 |
| 河流 | `waves` | `blue` | — | 3.0 |
| 山脉 | `mountain` | `violet` | — | 3.0 |
| 道路 | `route` | `teal` | — | 3.0 |

注意「国家 → 省份 → 城镇 → 地点」是一条**可嵌套的链**，
而「河流 / 山脉 / 道路」是**平的**（没有下一级，不参与树的嵌套）。

每一级要建哪些属性，定义在 `GEO_PROPERTIES`：

| 级别 | 属性（名称 → 值类型） |
| --- | --- |
| 国家 | 全称(文本)、政体(文本)、首都(文本)、文化(文本)、面积(数字)、人口(数字)、颜色(文本) |
| 省份 | 所属国家(文本)、省会(文本)、面积(数字)、人口(数字) |
| 城镇 | 所属国家(文本)、所属省份(文本)、人口(数字)、类型(文本)、分组(文本)、坐标(文本) |
| 地点 | 所属(文本)、坐标(文本) |
| 河流 | 长度(数字)、流域(文本)、坐标(文本) |
| 山脉 | 所属(文本)、坐标(文本) |
| 道路 | 类型(文本)、端点(文本)、坐标(文本) |

> 这里跨级的引用（比如「首都」「所属国家」）**先存名字文本**，不直接存引用。
> 因为地图抽出来的就是名字，要变成真正的引用还需要再做一轮映射；
> 用户想改成真正的引用属性，随时可以在类型面板里改。

建类型的函数 `ensure_geo_types()` 用 `get_or_create`，是**可重入**的：

```python
entity_type, _ = EntityType.objects.get_or_create(
    world=world, name=kind,
    defaults={"icon": spec["icon"], "color": spec["color"], "position": index},
)
```

所以**重复导入不会长出第二套类型**，第二次导入复用第一次建好的。

### 5.2 方向一：地图实体 → 卡片（`import_entities`）

接口：`POST /api/world/maps/<doc_id>/import-entities`。

前端先从地图引擎的 `pack` 里把实体抽成扁平 JSON（**服务端仍然不解析 `map_data`**），
载荷长这样：

```json
{
  "nodes": [
    {
      "kind": "国家", "name": "临江国", "x": 30, "y": 40,
      "attrs": {"政体": "君主制", "人口": 1200000},
      "children": [
        {"kind": "省份", "name": "北境", "x": 28, "y": 36,
         "children": [{"kind": "城镇", "name": "石头城", "x": 27, "y": 35}]}
      ]
    }
  ],
  "flat": [
    {"kind": "河流", "name": "青水", "x": 44, "y": 52, "attrs": {"长度": 320}}
  ]
}
```

- `nodes` 是**有嵌套**的实体树（国家 → 省份 → 城镇 → 地点）。
- `flat` 是**平的**实体（河流、山脉、道路）。

导入算法：

```
① ensure_geo_types(world)     保证七个类型都在（缺什么建什么）
② geo_folder(world, "地理")    取得 / 建「地理」根文件夹
③ 遍历 nodes：
     place(kind, 父文件夹, 节点, 序号)
       - 认得出 kind 且 name 非空 → _upsert_card()（同名同级就地更新）
       - 建 / 更新对应的图钉 _pin()
       - 递归处理 children（只允许「层级内的下一级」）
④ 遍历 flat：
     把每个实体放进「地理」下按类型命名的兜底文件夹，再 place()
⑤ 返回统计：counts / created / updated / markers / types
```

几个关键点：

- **同名同级是「就地更新」，不是重复新建。** `_upsert_card()` 先按
  `(world, card, parent, name)` 找已有卡片，找到就更新它的属性值，找不到才新建。
  所以你**长完地图再导一次，不会把整棵树复制一遍**。
- **统计里 `counts`（处理了几个）与 `created`（新建了几张）是两回事。**
  因为地图上同名的同级条目（比如同一个省里两座同名小镇）会并成一张卡——
  处理了 5 个、实际新建 3 张，两个数都要报出去。
- **只做「层级内」的嵌套。** 如果某个 `children` 里的 kind 不是当前级的下一级，
  `place()` 会强行把它掰回链条上的下一级，避免把树拧成麻花；
  河流之类的非层级实体一律走 `flat`。
- **`_pin()` 用 `get_or_create(document, card)`。** 同一张卡片在同一张地图上
  只会有一个图钉，重复导入只是把图钉的 `name` / `x` / `y` 更新一遍。

`_upsert_card()` 还会顺手给卡片写一段「概览」区块，免得点进去是一片空白：

```python
lines = [name]                       # 第一行是名字
for field in OVERVIEW_FIELDS.get(kind, []):  # 按类型挑几项关键信息
    lines.append(f"{field}：{attrs[field]}")
```

「概览显示哪几项」由 `OVERVIEW_FIELDS` 决定，比如国家显示「全称 / 政体 / 首都 / 人口」。

### 5.3 方向二：卡片 → 地图（`distribute` 自动铺开下一级）

接口：`POST /api/world/documents/<doc_id>/distribute`，
请求体 `{"count": N}`。

给它一个地理条目（比如「临江国」），它会**自动生成下一级**（省份）的卡片 + 图钉。
这是「先搭好骨架，细节慢慢填」的加速器。

数量怎么定：

```python
total = count if count > 0 else _auto_count(parent)
```

- 手填 `count > 0` 就用手填的。
- 给 0 或负数则**按父级的「面积」自动算**：
  `面积 ÷ 400`，并夹在 `2 ~ 12` 之间；没面积就给中位数 4。

```python
return int(max(SPREAD_MIN, min(SPREAD_MAX, round(area / SPREAD_AREA_PER_CHILD))))
# SPREAD_AREA_PER_CHILD = 400.0, SPREAD_MIN = 2, SPREAD_MAX = 12, SPREAD_DEFAULT = 4
```

位置怎么定——**确定性撒点**（这是这个函数最关键的设计）：

```python
def _seed(document) -> int:
    """同一条目每次铺出来的结果要一样：用它的 id 与名字派生一个稳定种子。"""
    return abs(hash(f"{document.id}:{document.name}")) % 9973
```

```
for index in range(total):
    angle  = (index / total) * 2π + (seed % 360) * π/180   # 绕父级一圈
    radius = spread * (0.45 + 0.55 * ((index + 1) / total)) # 从内圈到外圈递进
    x = 锚点x + cos(angle) * radius
    y = 锚点y + sin(angle) * radius * 0.7                   # y 轴压扁一点更像地图
```

- **锚点**：默认取父级的图钉位置（`MapMarker.objects.filter(card=parent)`）；
  没有图钉就落在正中央 `(50, 50)`。
- **半径随层级缩小**（`spread`）：国家的孩子撒在 12% 范围，城镇的孩子只有 2.5%。
- **种子固定**：同一个父级每次铺出来的位置一模一样，所以**不会越点越乱**，
  用户手改过也能改得回来。

名字怎么起——`父名 + 「·」 + 后缀`，例如「临江国·北境」「石头城·北郊」：

| 子级 | 后缀池 |
| --- | --- |
| 省份 | 北境、南境、东境、西境、中州、上郡、下郡、腹地、边郡、外郡 |
| 城镇 | 城、镇、港、关、堡、驿、寨、市、屯、戍 |
| 地点 | 北郊、渡口、山隘、旧垒、盐场、林地、石桥、古渡、草甸、崖上、溪口、南陌 |

后缀池用完了就用兜底池（一号、二号…八号）。字符串形如 `parent.name + "·" + suffix`
让人**一眼知道这个条目从哪来**，用户再按需要改名。

生成的每个下级还会把「所属」属性串起来（`所属 = 父名`，
`所属国家 / 所属省份` 从父级继承或取父名），并在属性里记一行 `坐标`。

### 5.4 坐标与引用关系如何维护

| 关系 | 靠什么维持 |
| --- | --- |
| 图钉 ↔ 条目 | `MapMarker.card` 外键指回卡片文档 |
| 区域 / 文字 ↔ 卡片 | 同样用 `MapMarker.card`（可以为空） |
| 条目在地图上的位置 | `MapMarker.x` / `y`（百分比），或区域的 `points` |
| 卡片之间的归属 | 文档树的 `Document.parent`（`_upsert_card` 按 parent 组装层级） |
| 属性里的归属（名字文本） | 卡片属性值，导入时写入 |
| 铺开的新图钉挂哪张地图 | 父级图钉所在的那张地图；没有就回退世界第一张地图 |

`distribute` 里有一段专门解决「新图钉该挂哪张地图」：

```python
anchor = MapMarker.objects.filter(card=document).select_related("document").first()
map_doc = anchor.document if anchor is not None else (
    Document.objects.filter(world=world, document_type=DOC_MAP, deleted_at__isnull=True)
    .order_by("position", "id").first()
)
```

优先跟着父级已经在用的地图走，找不到就退回世界里的第一张地图。

## 6. 接入第三方幻想地图生成器（Azgaar FMG）

地图引擎用的是 **Azgaar 的 Fantasy Map Generator（MIT 协议）**。
接入方式有一个很重要的原则：**构建产物入库，运行时不需要 Node。**

| 环节 | 做法 |
| --- | --- |
| 源码 | vendored 在 `third_party/fantasy-map-generator` |
| 构建 | `tools/build_map.py` 把它构建到 `static/map/vendor` |
| 产物 | 已提交进仓库，**线上直接静态提供，运行时不需要 Node / 构建步骤** |
| 页面模板 | `templates/map/app.html` 是构建期生成的；要改结构改上游 `src/index.html`，要改外观走本地覆盖样式 |

`static/map/` 目录下是构建出来的资源：

```
static/map/
├── vendor/
│   ├── index.html / index-*.js / index.css   页面与打包脚本
│   ├── libs/          d3、three、jquery、jszip… 第三方库
│   ├── styles/        各种地图风格的 JSON
│   ├── images/        图标、纹理、风格预览图
│   └── heightmaps/    ★ 高度图（底图）与导入规则
├── panel.css / shell.css / tokens.css         工作台自己的外壳样式
```

### 6.1 高度图与导入规则

`static/map/vendor/heightmaps/` 里是一批 `.png` 高度图（`world.png`、`europe.png`、
`east-asia.png`、`mediterranean-sea.png` …），供地图引擎「按高度图生成地形」用。
旁边有一份 `import-rules.txt`，说明了**怎么做出符合要求的高度图**：

```text
To get heightmap with correct height scale:
1. Open https://tangrams.github.io/heightmapper
2. Toggle off auto-exposure
3. Set max elevation to 2000
4. Set min elevation to -500
5. Find region you like
6. Render image
7. Optionally rescale image to a smaller size (e.g. 500x300px) as high resolution is not used
```

翻译成人话，就是一套「统一海拔标尺」的规矩：

1. 打开在线高程图工具；
2. **关掉自动曝光**（否则每张图亮度标准不一样，拼在一起会错位）；
3. 最高海拔设 2000，最低设 -500（固定范围 → 高度可解释、可复现）；
4. 选一片想要的区域，渲染成图；
5. 可以缩到小尺寸（如 500×300），因为用不到那么高的分辨率。

为什么强调这套规矩：地图引擎是把图片的**亮度**当成**海拔**读的。
如果不同图片用了不同的曝光/范围，同一个亮度在两张图上就代表不同高度，
生成出来的地形就会忽高忽低、接不上。统一标尺才能保证「白 = 高山、黑 = 深海」到处一致。

## 7. 相关接口清单

工作区地图接口都挂在 `/api/world/` 下（路径结尾不带斜杠），定义见 `apps/world/urls.py`：

| 方法 | 路径 | 视图 | 作用 |
| --- | --- | --- | --- |
| GET | `/api/world/maps/<doc_id>` | `map_state_view` | 地图状态：图层 + 标注 + 背景与视野 + 可选kind/颜色 |
| GET / PUT | `/api/world/maps/<doc_id>/data` | `map_data_view` | 取 / 换整包 `map_data`（不透明文本；PUT 需要编辑权限） |
| POST / DELETE | `/api/world/maps/<doc_id>/background` | `map_background` | 设置底图：上传文件 / 粘贴 URL / `clear=1` 清空 |
| POST | `/api/world/maps/<doc_id>/layers` | `map_layer_collection` | 加一个图层 |
| GET / PUT / DELETE | `/api/world/map-layers/<layer_id>` | `map_layer_detail` | 读 / 改（名字、显隐、不透明度）/ 删（至少留一个） |
| POST | `/api/world/maps/<doc_id>/markers` | `map_marker_collection` | 加一个标注（可吸附一张卡片） |
| GET / PUT / DELETE | `/api/world/map-markers/<marker_id>` | `map_marker_detail` | 读 / 改（位置、形状、颜色、吸附的卡）/ 删 |
| POST | `/api/world/maps/<doc_id>/import-entities` | `map_import_entities` | 地图实体 → 卡片 + 图钉（`geo.import_entities`） |
| POST | `/api/world/documents/<doc_id>/distribute` | `document_distribute` | 给地理条目自动铺开下一级（`geo.distribute_children`） |

独立页面（非 JSON 接口）：

| 方法 | 路径 | 视图 | 作用 |
| --- | --- | --- | --- |
| GET | `/map` | `mapdoc.map_home` | 302 跳到默认档 `/map/2d` |
| GET | `/map/<view>` | `mapdoc.map_page` | 地图页（`2d` / `3d`），支持 `?doc=`、`?embed=`、`?theme=` |

> 注意几个「权限收紧」的地方：`map_data` 的 PUT（整包覆盖不可逆）会额外再判一次
> `permissions.can_edit`，和其它写接口比更谨慎；独立页若不是可编辑成员，会强制 `readonly`。
