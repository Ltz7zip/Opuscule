# 发布与只读站点

> **文档版本：0.5.0-dev**
>
> 这份文档讲清楚一件事：**一个在「工作区」里写好的世界，怎么变成给读者看的只读网站。**
> 内容覆盖发布的语义、发布状态机、只读站点的每一类页面、全文搜索算法、密码档解锁流程，
> 以及相关的接口与路由。读之前，你只需要知道：「工作区」是作者用来写的地方，
> 「只读站点」是读者用来读的地方，两者跑在同一个 Django 进程里。

---

## 1. 一句话理解「发布」

把世界想象成一本手稿。**发布**不是把书拿去印刷、影印一份出来，而是：

> 在手稿前面立一块"已开张"的牌子，并且给读者发一张写着当前页码的书签。

真正的书稿一直只有一份，躺在数据库里。读者每次翻开，都是**当场**从这份书稿里渲染出来的。
所以「重新发布」只是把页码书签往前挪一格；「下线」只是把招牌摘下来，书稿一个字都没丢。

这条"即时渲染"的设定，后面第 4 节会展开讲。先把两层字段理清楚。

---

## 2. 两层发布字段：站点级与文档级

发布涉及两个层级的字段。可以类比成"书店开不开门"（站点级）和"这本书上不上架"（文档级）。

### 2.1 站点级字段（存在 `World` 表上）

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `is_published` | 布尔 | 站点是否"已开张"。为假时，只读站点一律 404 |
| `published_slug` | 字符串 | 站点短码，构成公开地址 `/s/<短码>/`。第一次发布时生成 |
| `audience` | 选项 | 访问范围：`public`（任何人可读）/ `unlisted`（仅持链接可见）/ `password`（需要密码） |
| `publish_password` | 字符串 | 当 `audience = password` 时要求的访问密码（最多 60 字） |
| `publish_version` | 整数 | 发布版本号。**每次发布 +1**，站点页脚显示 `v<版本>` |
| `published_at` | 时间 | 站点最后一次发布的时刻 |

`audience` 的三个取值和它们对读者的约束：

| 取值 | 中文标签 | 谁能看到 | 会被搜索引擎收录吗 |
| --- | --- | --- | --- |
| `public` | 任何人可读 | 任何人 | 会（正常索引） |
| `unlisted` | 仅持链接可见 | 拿到链接的人 | 不会（页面带 `noindex`） |
| `password` | 需要密码 | 输入正确密码的人 | 不会（页面带 `noindex`） |

> 注意：`unlisted` 和 `password` 都会给页面加上 `<meta name="robots" content="noindex, nofollow">`，
> 让搜索引擎别收录（逻辑在 `site_views._site_base()` 里：`noindex = audience != "public"`）。
> 但它们**都还是"读永远公开"的**：不登录也能访问，只是需要链接或密码而已。

### 2.2 文档级字段（存在 `Document` 表上）

每一份文档（卡片、时间线、地图……）自己也有发布相关的字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `is_published` | 布尔 | 这份文档**是否包含进站点**（默认 `True`，即默认都上站） |
| `hidden` | 布尔 | 是否**在维基里隐藏**。隐藏的文档即使 `is_published=True` 也不上站 |
| `published_version` | 整数 | 它上次进入站点时的发布版本号 |
| `published_at` | 时间 | 它上次进入站点的时刻（**状态机判断的关键**） |

### 2.3 两层怎么配合

一句话：

> **站点级决定"门开不开"，文档级决定"这份文档上不上架"，时间戳决定"上架之后有没有被偷偷改过"。**

`site_documents(world)` 就是"上架清单"的来源，它同时卡住三个条件：

```python
def site_documents(world):
    # 站点没开张 → 谁都不给看
    if not world.is_published:
        return Document.objects.none()
    return world.documents.filter(
        deleted_at__isnull=True,          # 没进回收站
        hidden=False,                     # 没被隐藏
        is_published=True,                # 被包含进站点
        document_type__in=SITE_DOC_TYPES, # 类型本身有站点页面（见第 6 节）
    ).order_by("document_type", "position", "id")
```

只要这四项里任意一项不满足，这份文档就不会出现在只读站点上。

## 3. 发布状态机：五个状态

工作区的分享面板会给每份文档标一个状态，告诉你"发布之后它有没有变过"。五个状态的含义：

| 状态常量 | 界面含义 | 什么时候是它 |
| --- | --- | --- |
| `unpublished` | 没包含进站点 | 整个站点还没发布过（`publish_version == 0`） |
| `pending` | 已包含、还没上过站 | 站点发布过，但这份文档是后加的（`published_at` 为空） |
| `live` | 已上站且没再改过 | 上过站，且之后 `updated_at` 不晚于 `published_at` |
| `stale` | 上过站但之后改过 | 上过站，但 `updated_at` 比 `published_at` 新 |
| `excluded` | 被排除 | `hidden=True` 或 `is_published=False` |

`stale` 就是界面上那句 **"Edited since you published"**：文档已经改过，但你还没重新发布，
站点上现在挂着的是旧内容。

### 3.1 判断逻辑（伪代码）

判断依据完全是**时间戳的先后**，而不是版本号。实现在 `apps/world/models/constants.py` 的 `publish_state()`：

```text
publish_state(document):
    world = document.world

    # ① 文档自己没被收录（隐藏 or 未包含）→ 被排除
    if document.hidden or not document.is_published:
        return "excluded"

    # ② 整个站点还没发布过 → 未发布
    if not world.is_published or world.publish_version == 0:
        return "unpublished"

    # ③ 收录了，但还没随任何一版上过站 → 待发布
    if document.published_at is None:
        return "pending"

    # ④ 上过站，但之后又被改过 → 已过期
    if document.updated_at and document.updated_at > document.published_at:
        return "stale"

    # ⑤ 上过站，且没再改过 → 在线
    return "live"
```

### 3.2 一个对照例子

假设现在的时刻是第 10 天：

| 文档 | `published_at` | `updated_at` | 状态 | 为什么 |
| --- | --- | --- | --- | --- |
| `A` | 第 5 天 | 第 5 天 | `live` | 上过站后没动过 |
| `B` | 第 5 天 | 第 8 天 | `stale` | 第 8 天改过，比第 5 天新 |
| `C` | 空 | 第 9 天 | `pending` | 从没上过站 |
| `D` | 第 5 天 | 第 5 天 | `excluded` | 虽然上过站，但现在 `hidden=True` |

> 小提醒：`updated_at` 用的是 Django 的 `auto_now`——只要模型被保存一次，它就会刷新成当前时间。
> 项目里专门有一个 `touch_document()` 来在"内容改动"时保存文档，把它顶新（见第 10 篇文档）。

## 4. 「即时渲染」是什么意思

这是整个发布体系最核心的设计决定，值得单独讲。

### 4.1 不是快照，是现场渲染

有些系统发布时会**把当前内容拍一张快照存起来**，站点读的是快照；改工作区不会立即影响站点，
必须"再发布一次"才会更新。

Opuscule 不这么做。只读站点的每个页面（`apps/world/site_views.py` 里那些视图）都是**每次请求时**
直接从数据库的 `Document` / `Card` 表里读当前内容、现场渲染 HTML 的。

### 4.2 那「发布」到底做了什么

看 `apps/world/services/publish.py` 的 `publish()`，它做的事只有四件：

1. 读一次"差异预览"（第 5 节），先算清楚这次发布会新增 / 更新 / 下架哪些文档；
2. 如果传了访问范围 / 密码，更新站点级字段；
3. **把版本号 `+1`**，写上 `published_at`，标记 `is_published=True`；
4. 把"该上站"的文档批量打上这个新版本号（同时刷新它们的 `published_at`），
   再写一条 `PublishLog` 发布记录。

关键点在第 3、4 步：**"重新发布"本质上只是推进版本号、刷新文档的时间戳**。
因为站点是现场渲染的，改了内容不需要"拷贝"到任何地方——读者下次刷新页面时，
看到的自然就是新内容（前提是你点了发布，把 `published_at` 顶到 `updated_at` 之后，
这样文档状态才会从 `stale` 回到 `live`）。

```text
publish(world):
    diff = publish_preview(world)          # ① 先算差异
    更新 audience / password（如果传了）
    如果还没有 published_slug：生成一个
    world.is_published = True
    world.publish_version += 1             # ② 推进版本号
    world.published_at = now
    保存 world
    # ③ 把未删除、未隐藏的文档都标记成本版本
    targets = world.documents.filter(deleted_at__isnull=True)
    targets.update(published_version=version, published_at=now)
    # ④ 留一条发布记录
    PublishLog.objects.create(world, version, audience, counts, added, changed, removed, author)
```

> 代码里 `publish()` 外面套了 `@transaction.atomic`，保证这几步要么全成功、要么全回滚，
> 不会出现"版本加了但文档没跟上"的中间状态。

### 4.3 下线（unpublish）不删数据

`unpublish()` 只做一件事：

```python
def unpublish(world):
    world.is_published = False
    world.save(update_fields=["is_published"])
```

把 `is_published` 置假后，`_get_world()` 就会给所有站点请求抛 404——**站点立刻消失**。
但**内容一个都没删**，`publish_version`、`published_slug`、每条发布记录都原样留着。
等你想重新开张，再点一次发布，版本号会在原来的基础上继续往上加。

> 为什么要这样设计？因为"下线"通常只是临时动作（不想让人看到了 / 想先改完再放出来），
> 如果连数据和版本号一起清掉，重新上线时读者看到的版本号会倒退，发布历史也断了。

## 5. 发布差异预览 `publish_preview()`

在真正发布之前，工作区会先调 `publish_preview(world)` 算一遍"这次发布会发生什么"，
好在界面上列出「将新增 / 将更新 / 将下架」的清单。

实现思路（`apps/world/services/publish.py`）：

1. 遍历所有未删除、非文件夹的文档，对每一份调用 `publish_state()` 得到当前状态；
2. **特殊情况**：如果这是**第一次发布**（站点还没开张），那么所有 `unpublished` 的文档
   在这次发布后都会变成"新增"，所以先把它们的状态临时改判成 `pending`；
3. 按状态分桶：

| 分桶 | 收录哪些状态 | 含义 |
| --- | --- | --- |
| `added`（新增） | `pending` | 还没上过站，这次会上站 |
| `changed`（更新） | `stale` | 上过站但改过了，这次会把新内容推上去 |
| `removed`（下架） | `excluded` / `unpublished`，以及"已删除但曾被发布"的文档 | 站点上不再收录 |

4. 每条记录带上 `id` / `name` / `type` / `state` / `updated_at`，最后给一个
   `summary` 汇总三个桶的数量。

返回结构大致长这样：

```json
{
  "added":   [{"id": 12, "name": "银月港", "type": "card", "state": "pending", "updated_at": "..."}],
  "changed": [{"id": 7,  "name": "大灾变", "type": "timeline", "state": "stale", "updated_at": "..."}],
  "removed": [{"id": 3,  "name": "旧草稿", "type": "card", "state": "excluded", "updated_at": "..."}],
  "summary": {"added": 1, "changed": 1, "removed": 1}
}
```

### 5.1 `publish_summary()`：站点状态汇总

除了预览，`World.publish_summary()` 会把站点状态打包给前端分享面板，包含：
`published`（是否已发布）、`url`（站点地址）、`audience`、`has_password`、`version`、
`published_at`，以及五个状态的**文档计数** `counts`。

## 6. 只读站点的页面类型

只读站点不是每一种"文档"都会出版。哪些文档类型拥有站点页面，由一个白名单常量决定。

### 6.1 `SITE_DOC_TYPES`：拥有站点页面的类型

`apps/world/services/publish.py` 里的白名单：

```python
SITE_DOC_TYPES = (
    DOC_CARD,      # 卡片
    DOC_TIMELINE,  # 时间线
    DOC_MAP,       # 地图
    DOC_GRAPH,     # 世界图谱
    DOC_CANVAS,    # 画布
    DOC_NOTE,      # 笔记
    DOC_TABLE,     # 表格
    DOC_TREE,      # 关系树
)
```

只有 `document_type` 落在 `SITE_DOC_TYPES` 里的文档，才会出现在站点上。
其余类型（文件夹、看板、词典、待办、骰子、环境音、雷达图、章节、媒体库等）**不会出版**——

| `document_type` | 中文 | 站点有页面吗 | 说明 |
| --- | --- | --- | --- |
| `card` | 卡片 | 是 | 站点的基本单位，一卡一页 |
| `timeline` | 时间线 | 是 | 独立页面，事件按时间排 |
| `map` | 地图 | 是 | 页面内嵌**只读画布** |
| `familyTree` | 关系树 | 是 | 页面内嵌只读画布 |
| `graph` | 世界图谱 | 是 | 页面内嵌只读画布 |
| `canvas` | 画布 | 是 | — |
| `note` | 笔记 | 是 | — |
| `table` | 表格 | 是 | — |
| `folder` | 文件夹 | 否 | 纯容器，不出独立页 |
| `board` | 看板 | 否 | 工作台视图 |
| `dictionary`/`todo`/`voice`/`dice`/`soundscape`/`radar`/`chapter`/`media`/`embed` | 词典/待办/语音/骰子/环境音/雷达图/章节/媒体库/嵌入 | 否 | 工具型文档，不出版 |

> 判断"有没有内嵌画布"的地方在 `site_views.page()`：当文档类型是 `map` / `familyTree` / `graph`
> 时，页面会把工作区的**只读画布**嵌进来（`canvas_embed = True`）。

### 6.2 站点页面清单

`apps/world/site_views.py` 提供了下面这些页面／资源，路由挂在 `/s/<短码>/` 下：

| 页面 | 视图 | 作用 |
| --- | --- | --- |
| **首页** | `home` | 按类型分组的卡片网格；支持类型 / 纪元筛选、`?q=` 内联搜索 |
| **文档页** | `page` | 一张卡 / 一条时间线 / 一页地图（内嵌只读画布）的详情页 |
| **纪元页** | `era_page` | 某个纪元的说明 + 该纪元里的事件（按时间排） |
| **搜索页** | `search` | 站点全文搜索，命中处高亮，支持"加载更多" |
| **密码页** | `_gate` / `unlock` | 密码档站点未解锁时展示的输入页 |
| **404 页** | `_missing_document` | 找不到文档时的"信号丢失"页（区分"曾经有"和"从来没有"） |
| **RSS 订阅** | `feed` | `/s/<短码>/feed.xml`，读者丢进阅读器就能追更 |
| **分享卡片** | `og_card` | `/s/<短码>/og.svg`，社交平台预览用的 SVG（1200×630） |

### 6.3 一个页面的公共上下文

这些页面共用 `_site_base()` 组装的一部分上下文：世界、世界主题、明暗模式、访问范围标签、
按类型分好的 `sections`、筛选选项、纪元列表、当前搜索词、当前筛选状态。其中：

- `theme_mode`：站点的明暗跟随世界主题（`light` / `dark`），模板写到 `<html data-theme>`；
- `noindex`：非公开站点为 `True`，模板据此加 `noindex` meta；
- `sections`：由 `site_sections()` 按卡片类型分组（时间线单独一组）。

## 7. 站点全文搜索 `search_documents()`

读者在站点里搜关键词时，走的是 `publish.py` 的 `search_documents(world, keyword)`。
它有一个非常重要的约束：

> **只搜"会出版"的文档。** 搜索的候选集来自 `site_documents(world)`，
> 所以草稿、隐藏的、没包含进站点的内容，访客一个字都搜不到。

### 7.1 搜哪些字段

对每份候选文档，把下面这些来源拼成一大段 `haystack`（用换行连接）：

| 来源 | 说明 |
| --- | --- |
| 文档名 | `document.name` |
| 别名 | 卡片的所有 `aliases` |
| 正文纯文本 | `card.body` |
| 区块文字 | `blocks_to_text(card.blocks)`——把富文本区块拍平成纯文本 |
| 属性值 | 值类型是字符串 / 数字 / 浮点的属性值 |
| 事件标题 | 该文档下所有时间线事件的 `title` |

只要关键词在 `haystack` 里出现（或命中了某个事件标题），就算一条结果。

### 7.2 排序权重

命中之后要决定"谁排前面"。规则是**命中位置越"要紧"，分越高**：

| 权重 | 命中位置 | 含义 |
| --- | --- | --- |
| `100` | 名字**以关键词开头** | 最贴合，如搜「银月」命中「银月港」 |
| `80` | 关键词在名字**中间** | 如搜「月港」命中「银月港」 |
| `60` | 命中**别名** | 别名也是这个实体的名字 |
| `40` | 命中**正文** | 正文提到 |
| `35` | 命中**事件标题** | 出现在事件名里 |
| `20` | 其它（属性值等） | 最弱 |

排序时：`sort(key=lambda item: (-item["score"], item["name"]))`——**先按分数从高到低，
分数相同再按名字字典序**。最多返回 `limit`（默认 400）条。

### 7.3 命中片段怎么切成 `parts`

模板要给出命中处加 `<mark>` 高亮，但又不想在前端再算一遍，所以后端直接把片段切成
一个数组 `parts`：每项是 `{"text": "...", "hit": True/False}`，`hit=True` 的就是命中处。

切法（`split_parts()`）：

1. 取命中位置**前 40 字、后 60 字**组成一个"窗口"（把换行换成空格），作为 `snippet`；
2. 在这个窗口里，从前往后**找出所有命中**（大小写不敏感，一处不漏）；
3. 每段非命中文本记 `hit=False`，每段命中文本记 `hit=True`；
4. 一段都没命中时，返回整段作为 `hit=False`，保证 `parts` 非空。

模板里就能这样写（`templates/site/search.html`）：

```html
<p class="hit-snippet">
  {% for part in hit.parts %}
    {% if part.hit %}<mark>{{ part.text }}</mark>{% else %}{{ part.text }}{% endif %}
  {% endfor %}
</p>
```

### 7.4 筛选与分页

- **筛选**：搜索页支持 `?type=<实体类型id>` 和 `?era=<纪元id>`。带筛选时，
  先算出允许的文档 id 集合，只保留命中集合里的这些（`search()` 里的 `allowed` 逻辑）。
- **分页**：站点列表用「加载更多」而不是翻页。`paginate()` 每次给一页，
  请求参数 `?show=` 决定这次显示多少条（夹在 20~200 之间，默认 20），
  下一次点"加载更多"就是再 +20 条。

## 8. 「你是不是想找」：`suggest_similar()`

搜不到结果时，页面上会出现一句"你是不是想找：……"。这就是 `suggest_similar(world, keyword)`。

它的实现基于 Python 标准库的 `difflib`：

```python
import difflib

def suggest_similar(world, keyword, limit=5):
    keyword = (keyword or "").strip()
    if len(keyword) < 2:
        return []
    # 拿所有已发布文档的名字建一个字典
    names = {document.name: document for document in site_documents(world)}
    # difflib 找出"足够像"的名字（相似度 cutoff=0.6）
    close = difflib.get_close_matches(keyword, list(names), n=limit, cutoff=0.6)
    if not close:
        # 近似匹配没有 -> 退化成"包含关系"匹配
        lowered = keyword.lower()
        close = [name for name in names
                 if lowered in name.lower() or name.lower() in lowered][:limit]
    return [{"name": name, "slug": names[name].slug, "type": names[name].document_type}
            for name in close]
```

关键点：

- **长度 < 2 直接返回空**。太短的关键词做近似匹配会到处乱推荐。
- `difflib.get_close_matches` 用的是 **SequenceMatcher 相似度**，`cutoff=0.6` 表示
  相似度低于 0.6 的名字不算"像"。
- 近似匹配捞不到东西时，**退化成"互相包含"匹配**：关键词是名字的子串、或名字是关键词的子串。

## 9. 密码档站点的解锁流程

当世界的 `audience = password` 且有 `publish_password` 时，读者必须先解锁才能看。这套机制
不依赖登录，而是**把"已解锁"记在读者自己的会话（session）里**。

### 9.1 判断与放行

```python
def _unlock_key(world):
    return f"site_unlocked_{world.id}"     # 每个世界一个独立的标记

def can_view(world, session):
    # 不是密码档，或没设密码 -> 直接放行
    if world.audience != AUDIENCE_PASSWORD or not world.publish_password:
        return True
    return bool(session.get(_unlock_key(world)))   # 会话里有没有这个标记

def unlock(world, session, password):
    if world.audience != AUDIENCE_PASSWORD or not world.publish_password:
        return True
    if (password or "").strip() == world.publish_password:
        session[_unlock_key(world)] = True         # 记下"这个世界的这个会话已解锁"
        return True
    return False
```

### 9.2 页面级的"闸门"

所有站点页面进来第一件事都是调 `_gate(request, world)`：

- `can_view()` 为真 → 返回 `None`，正常渲染页面；
- 为假 → 渲染 `templates/site/password.html`（密码输入页），页面请求就此短路。

### 9.3 提交流程

密码页的表单 POST 到 `/s/<短码>/unlock`，由 `unlock` 视图处理：

| 结果 | 行为 |
| --- | --- |
| 密码正确 | 在会话里写入 `site_unlocked_<world_id> = True`，然后 **302 跳回站点首页** |
| 密码错误 | 重新渲染密码页，带上 `error=True`，返回 **403** |

> 为什么用 `session` 而不是 Cookie 明文？因为会话数据是**服务端**保存、浏览器只拿一个
> 随机会话 id 的，密码本身和"已解锁"标记都不会出现在浏览器里。
> 另外每个世界用不同的 key（`site_unlocked_<id>`），所以在 A 世界解锁了不会顺带解锁 B 世界。

## 10. 相关接口与路由

### 10.1 发布相关接口（工作区用，挂在 `/api/world/` 下）

| 方法 | 路径 | 视图 | 作用 |
| --- | --- | --- | --- |
| GET | `/api/world/publish/preview` | `publish_preview_view` | 发布差异预览（新增 / 更新 / 下架） |
| GET | `/api/world/publish/log` | `publish_log_view` | 发布记录（最近 30 条） |
| GET | `/api/world/publish` | `publish_view` | 看站点状态：`publish_summary()` + 可选访问范围 |
| POST | `/api/world/publish` | `publish_view` | 发布 / 重新发布（可带 `audience` / `password`） |
| POST | `/api/world/unpublish` | `unpublish_view` | 下线站点（内容保留，站点立刻 404） |

> 这些接口都要经过写操作守门人（`apps/world/middleware.py`）：写方法 + 受保护路径 + 有编辑权限
> 才放行。权限模型见 [10-账号·协作·版本.md](10-账号·协作·版本.md)。

### 10.2 只读站点路由（读者用，挂在 `/s/` 下）

`apps/world/site_urls.py`（`app_name = "site"`）：

| 路径 | 名称 | 说明 |
| --- | --- | --- |
| `/s/<slug>/` | `site:home` | 站点首页 |
| `/s/<slug>/og.svg` | `site:og` | 分享卡片（SVG） |
| `/s/<slug>/feed.xml` | `site:feed` | RSS 订阅 |
| `/s/<slug>/search` | `site:search` | 站点搜索页 |
| `/s/<slug>/era/<era_id>` | `site:era` | 纪元页 |
| `/s/<slug>/unlock` | `site:unlock` | 密码档解锁（POST） |
| `/s/<slug>/<doc_slug>/` | `site:page` | 文档页 |

> **为什么用 `<str:slug>` 而不是 Django 的 `<slug:...>` 转换器？**
> 因为文档 slug 可能是中文（项目里的 `slugify_name` 保留了 Unicode 词字符），
> 而 `<slug:>` 只认 `[-a-zA-Z0-9_]`，会把中文 slug 挡在门外。
>
> 另外注意路由顺序：`og.svg`、`feed.xml` 这些固定路径必须排在 `<doc_slug>/` **之前**，
> 否则它们会被当成文档 slug 吃掉。

### 10.3 两个细节：文档按什么找、404 怎么区分

- `document_by_slug(world, slug)`：先按 `slug` 找，找不到再尝试把 slug 当数字 id 找
  （`slug.isdigit()` 时按主键兜底），但**只在"会出版"的文档里找**。
- 找不到时走 `_missing_document()`，它分两种 404：
  - **曾经有、现在没了**（slug 在库里对得上号，只是没发布 / 被隐藏 / 进了回收站）：
    告诉读者这儿原来是什么，并列出附近还开着的相关文档；
  - **纯信号丢失**（根本没这份文档）：给一个 glitch 风格的 404 和搜索框。
