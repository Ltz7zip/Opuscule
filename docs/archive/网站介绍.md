# 世界观共建 · 时间轴 —— 这是什么网站

> 一句话：**这是一个"建世界"的工作台，也是一台"讲故事"的出版机。**
> 你在一个工作区里把设定写成卡片、排成时间线、连成关系树、画成地图；
> 整理好之后，一键把它发布成一个读者可以直接浏览的只读网站。

---

## 1. 它解决什么问题

写小说、跑团、做游戏设定的人都会遇到同一件事：**设定越写越多，然后开始互相打架。**

- 三年前写的角色，去年改了名字，现在两处对不上；
- 时间线散在几个文档里，"大战"到底发生在"加冕"之前还是之后，得翻半天；
- 新读者想了解你的世界，你把一堆 Markdown 丢过去，对方根本不知道从哪看起；
- 和别人一起写的时候，改同一个文件，谁覆盖了谁说不清。

这个网站把"设定"从散落的文本变成**有结构、有关系、有时间、可发布**的数据：
每张卡片是一个实体（人物 / 地点 / 事件 / 物品……），卡片之间有引用关系，
事件挂在时间轴上有准确的时间点，而所有内容最终能汇成一个能给别人看的站点。

---

## 2. 三个身份，一份内容

同一份内容，网站提供三种完全不同的使用方式：

| 视角 | 谁在用 | 得到什么 |
| --- | --- | --- |
| **工作区**（`/world`） | 作者 | 文档树 + 多标签 + 并排面板的编辑器，所有工具都在这里 |
| **关系树页**（`/relationship`） | 作者 | 专门画族谱 / 组织结构的一整页网格画布 |
| **只读站点**（`/s/<slug>/`） | 读者 | 像维基一样的浏览界面，带搜索、纪元页、时间线、地图 |

**读永远公开，写需要权限。** 访客可以随便看发布出来的站点；要动内容得登录。
注册后会得到一个**属于自己的世界**（世界之间互不打扰），想和别人一起写就进对方的世界——
靠邀请码加入，角色（所有者 / 可编辑 / 只读）由邀请者定；第一个注册的账号成为初始世界的所有者。

## 3. 工作区里有什么

工作区是这个网站的主体。左侧是文档树，中间是文档区，右侧可以并排开第二个面板，
顶部是多标签——打开的东西像浏览器一样摊着，不用来回跳。

### 3.1 万能编辑器：卡片

"卡片"是世界里最基本的单位，一张卡片就是一个人、一座城、一场战争。

- **正文用块来写**：输入 `/` 唤出斜杠菜单，插标题、引用、提示框；块可以嵌套，也可以拖把手排序；
- **块级评论**：对着某一段正文直接评论、标记解决，不用另开文档；
- **自定义属性**：你自己定义"类型"（人物、地点、势力……），类型下面定义属性
  （文本 / 单选 / 多选 / 数字 / 日期 / 引用 / 公式）。之后所有这个类型的卡片都带着这些字段；
- **名字自动识别**：正文里写到一张已存在的卡片名或别名，就自动高亮成链接——
  中文没有词边界，用的是"最长匹配优先 + 不重叠"的策略；
- **纪元可见性**：同一张卡片，可以让它"只在这个纪元出现"或"在这个纪元里隐藏"，
  等于给世界留了版本分支。

### 3.2 时间线

这是项目最早做、也打磨最久的部分（`timeline` 应用就是从它来的）。

- 轴上放**时间点**（事件）和**时间段**（纪元色带）；悬停轴线出现 `+`，点一下就新建，边打边存，**没有保存按钮**；
- 滚轮缩放、拖拽平移、右键框选、多选整组拖动、`⌘Z` 撤销、删除走 Toast 的"撤销"而不是确认框；
- **自定义历法**：不一定是地球历。月份名、每月天数、每天小时数、卫星与月相周期都能自己定；
- **线视图 / 日历视图**两种看法，日历视图会画出月网格、当月事件和月相；
- **事件精度**分年 / 月 / 日 / 时刻，粗粒度的事件不用假装自己很精确；
- **纪元**既是时间段，也是世界的"版本"——顶栏切换纪元，界面整个跟着换一套可见性。

### 3.3 关系树

族谱、门派传承、公司组织、皇家宫廷，都是一张关系图。

- 从**模版**起步（家庭 / 公司 / 军事 / 皇家宫廷 / 从空白开始），模版自带一套现成关系词表；
- 右键长人、卡片四面加号、拖加号连线、关系类型菜单；
- 卡片严格贴网格，**关系线不必**——所以两代人之间的斜线是自然的；
- 独立页 `/relationship` 和工作区里的关系树面板**嵌的是同一份实现**，新功能两边自动都有。

### 3.4 地图、图谱，以及一堆工具

除了上面三样，工作区里还有一整套文档类型，都是"新建文档时选一个"就有：

| 类别 | 有什么 |
| --- | --- |
| **画布类** | 地图（图层 + 标记）、自由画布、关系树、世界图谱 |
| **数据类** | 表格（行 = 真卡片，列 = 属性，**双向绑定**，支持 CSV 导入导出）、看板 |
| **写作类** | 笔记、章节（带实时字数）、待办清单 |
| **造语 / 世界细节** | 词典（词形 / 读音 / 词性 / 释义）、骰子（可存档骰组）、环境音（WebAudio 实时合成雨 / 风 / 火 / 嗡鸣）、雷达图（把卡片的数值属性画成多维对比） |
| **素材** | 媒体库、语音备忘（浏览器直接录音）、链接嵌入 |

**世界图谱**是这些内容自动浮现出来的那张网：连线来自三个地方——卡片的引用属性、
时间线事件关联的卡片、正文里的名字提及（虚线）。你不必手动维护它，它反映了你实际写下的东西。

### 3.5 一个人写，还是几个人写

- **在线状态**：心跳式，顶栏显示"谁在这里"；
- **编辑冲突保护**：每份文档带修订号，你提交时对不上就返回 409 并把服务端最新内容带回来，
  界面提示"这份文档刚被别人改过，已刷新成最新内容"——**不会静默覆盖别人的改动**；
- **版本历史**：每次改动留快照（同作者 90 秒内的连续编辑合并成版，每份最多 30 版），
  可以预览、可以回滚，回滚本身也会先备份一版；
- **角色**：所有者（编辑 + 管成员 + 发邀请码）、可编辑、只读、游客。

### 3.6 进得来，出得去

- **导入**：Markdown 单文件 / 多选 / zip（Obsidian 目录会变成文件夹 + 卡片）、世界 JSON 还原，
  `[[双链]]` 接成卡片提及；
- **导出**：整个世界 zip（每份文档一个 Markdown + `world.json` 备份 + 媒体清单）、世界 JSON、
  单文档 Markdown / JSON；
- **回收站**：删除是软删除，随时还原；
- **建议**：本地规则找出"提到了但还没建卡的名字""空壳卡片""没人引用的文档""已经没关联的事件"，
  可以一键建卡；
- **撤销**：覆盖打字、拖拽排序、块菜单、属性、别名、评论，右键撤销按钮还能打开撤销历史跳回任意一步。

## 4. 发布：从工作台到网站

这是这个项目区别于普通笔记软件的地方——**设定不只是写给自己看的。**

编辑态和发布态是分开的两层：你在工作区里随便改，读者的站点不会跟着抖；
准备好之后点"发布"，才把这批内容推上去。发布预览会告诉你**这次会变什么**
（`publish.py` 里算出每个文档的四种状态：还没发布过 / 站点已发布但这是后加的 / 与站点一致 / 站点还是旧版），
每次发布还留一条记录。

发布出来的只读站点（`/s/<slug>/`）包括：

- **首页**：按分区陈列会出版的内容，带纪元区块和站点卡片；
- **搜索**：搜名称、别名、正文、区块文字、属性值和事件标题——只搜"会出版"的文档，草稿搜不到；
- **筛选**：按卡片类型或纪元筛，选项只列站点上真有的，还带数量；
- **纪元页**：`/s/<slug>/era/<id>/`，主题色标题 + 跨度 + 说明，按时间列出**属于这个纪元的事件**；
- **文档页**：每张卡片一个可分享的地址；
- **内嵌的可视化**：时间线、地图、关系树、图谱都能以只读画布嵌进站点页面里；
- **访问范围**：任何人可读 / 仅持链接可见 / 需要密码，三种都支持。

## 6. 技术栈

| | |
| --- | --- |
| 后端 | **Django 6.1.1** + SQLite + Django ORM（唯一依赖，`requirements.txt` 只有这一行） |
| 前端 | **原生 JavaScript / CSS**，没有构建步骤、没有 npm、没有前端框架 |
| 两个应用 | `timeline`（最早的单时间轴经典视图）、`world`（现在的世界工作区） |
| 静态资源 | `static/` 下按职责分层，40 个自绘 SVG 图标 |
| 测试 | `world/tests.py` + `timeline/tests.py` 共约 200 个测试，另有 `tools/` 下 20 多个浏览器端体验探针 |

历史值得一提：后端原本是 Flask，后来整体换成 Django（SQLite + ORM），
前端的交互则从"录屏一比一复刻"一路长成现在自成一体的工作区。
旧地址都留了跳转（`/` 和 `/w` 都 302 到 `/world`），已经发出去的链接不会失效。

## 7. 怎么跑起来

```bash
.venv/bin/pip install -r requirements.txt     # 装依赖
.venv/bin/python manage.py migrate            # 建表（幂等，db.sqlite3 里已有数据）
.venv/bin/python manage.py runserver          # http://127.0.0.1:8000
```

打开 `http://127.0.0.1:8000/` 会直接进工作区。想用 Django 自带的可视化后台，
先 `createsuperuser` 再访问 `/admin/`。

## 9. 它适合谁

- **小说 / 系列作品作者**：设定库 + 时间线 + 能给读者看的资料站；
- **跑团 GM / 世界观爱好者**：地图 + 关系树 + 纪元，玩家可以自己查；
- **游戏 / 影视前期设定**：把散落的设定文档收成有结构的库，还能导出 Markdown 交接；
- **任何"设定多到自己都记不清"的人**：让引用和提及自己浮出来（图谱 + 名字自动识别 + 建议）。
