## 3. 从数据里读出的 5 条设计原则

1. **边框是"暖调"，不是中性灰。** 浅色 `rgba(42,28,0,0.07)`（暖褐黑）、深色 `rgba(255,255,243,0.082)`（暖米白）。这是 Notion 手感的关键，换成 `rgba(0,0,0,.07)` 立刻变冷、变廉价。
2. **分割线用 `box-shadow` 的 inset，不用 `border`。** 实测侧边栏：`box-shadow: #F0EFED -1px 0 0 0 inset`，`border-right-width` 是 `0px`。
3. **层级靠字重和留白，不靠颜色。** 主/次文本亮度差极小（`#2C2C2B` → `#7D7A75`），一级层级主要靠 `400 / 700` 的字重差。
4. **侧边栏永远"浮起"一档**：深色时比画布**亮**（`#202020` > `#191919`），浅色时比画布**暗**（`#F9F8F7` < `#FFFFFF`）。
5. **点缀色只有一支蓝（`#2783DE`）**，且只出现在实心按钮/链接上。没有第二支强调色。

## 4. 与现有 Opuscule token 的冲突

`DESIGN.md` 当前是"VoltAgent 深空终端 × Ollama 文档克制 × Warp 块级温暖"。对照如下：

| 维度 | Opuscule 现状 | Notion 原味 | 冲突 |
| --- | --- | --- | --- |
| 画布 | `#0a0e12`（冷青近黑） | `#191919`（中性黑） | 中 |
| 主文本 | `#e8edf2`（冷白） | `#F0EFED`（暖白） | 中 |
| 主色 | `#00f0ff`（霓虹青） | `#2783DE`（沉稳蓝） | **高** |
| 强调色 | 品红 / 琥珀 / 荧光绿 / 蓝，共 4 支 | 无，只有 1 支蓝 | **高** |
| 语义编码 | 颜色编码状态（`--era-founding` / `--era-quiet` / `--era-broken`） | 字重 + 边框编码 | **最高** |

> ⚠️ 最难的**不是换色值，而是第 5 行**。Opuscule 用颜色表达"纪元状态"，Notion 用字重和边框表达层级。这是方法论层面的改造，涉及产品决策，不能靠改 CSS 变量解决。

## 7. 圆角尺度（实测）

扫描全站非零 `border-radius`，去重后得到 13 种取值。按语义归位：

| 用途 | 取值 | 证据 |
| --- | --- | --- |
| 小图标 / 头像 | `3.5px` / `4px` | `notion-record-icon`、行内 hover span、图片 |
| 侧栏行内按钮 | `4px` | `notion-sidebar-page-menu` |
| **按钮（主）** | **`6px`** | 顶栏 share / favorite / more、`notion-collection-add-view`、`notion-collection-edit-view`、`notion-table-view-add-row` / `add-column` |
| 卡片 / 菜单 | `12px` | 匿名容器（弹层） |
| 胶囊 / 圆形 | `9999px` / `1000px` / `100%` | `notion-sidebar-switcher`、`notion-close-sidebar`、`notion-ai-button` |

其他零散值：`16px`、`14px`、`3px`、`256px`、`0px 8px 8px 0px`（非对称，用于侧边面板）。

> 结论：Notion 的圆角**不是一套系统尺度**（3.5 / 4 / 6 / 12 / 14 / 16 / 256 / 9999 混用），有历史包袱。
> 我们建议收敛成 4 档：**`4` / `6` / `12` / `9999`**。

## 11. 阴影阶梯（实测）

取自 Notion CSS 的 `--c-shaBas*` / `--c-shaOut*`（同样按 `:root,.notion-light-theme` 与 `.notion-dark-theme` 两块分离）。

| 档 | 浅色 | 深色 |
| --- | --- | --- |
| sm | `0 4px 12px rgba(25,25,25,.027), 0 1px 2px rgba(25,25,25,.02)` | `0 2px 4px rgba(25,25,25,.08)` |
| md | `0 8px 12px rgba(25,25,25,.027), 0 2px 6px rgba(25,25,25,.027)` | `0 4px 12px -2px rgba(25,25,25,.08)` |
| lg | `0 20px 24px rgba(25,25,25,.05), 0 5px 8px rgba(25,25,25,.027)` | `0 14px 28px -6px rgba(25,25,25,.2), 0 2px 4px -1px rgba(25,25,25,.118)` |
| xl | `0 24px 48px rgba(25,25,25,.24), 0 4px 12px rgba(25,25,25,.14)` | `0 24px 48px rgba(25,25,25,.64), 0 4px 12px rgba(25,25,25,.56)` |

两个反直觉的点：

1. **深色的 alpha 反而更重**（sm `.027 → .08`、xl `.24 → .64`）。黑影压在深底上需要更高不透明度才看得见——和"深色更省墨"的直觉相反。
2. **`Out` 变体 = 基础影 + 一圈 1px 描边**，描边色就是边框色（深色 `#383836`、浅色 `rgba(42,28,0,.07)`）。也就是说 Notion 的"描边"在这套里是用 `box-shadow` 实现的，和侧边栏分割线同一手法。

已落进 `static/opuscule.css`，token 名 `--nb-shadow-{sm,md,lg,xl}` 与 `--nb-shadow-out-{sm,md}`；并把项目的"唯一一道投影" `--tx-shadow-modal` 指向了 xl 档。

## 12. 间距尺度（核查结论：Notion 没有）

搜遍 Notion CSS，**`--*spac*` / `--*gap*` 类 token 数量为 0**。它的间距是原子化 class 里写死的 px。

实测出现频率最高的值：`padding` 集中在 `0 / 4 / 8 / 12 / 16 / 20 / 24 / 32 / 48`，`gap` 集中在 `2 / 10 / 12 / 16 / 20 / 24 / 32`——**是 4px 基准，但混入大量 5/6/10/11/14/18/36/40 这种一像素级微调**，不是一套干净尺度。

**结论：这一项不用改。** 我们 `terminal.css` 的 `--tx-1..7`（4/8/12/16/24/32/48）已经和 Notion 的主力值一致，而且比它更规整。

### 经典时间线编辑器：按"只改配色、不动结构"处理

它是真正的例外——一套完全独立的 token。核实后发现它**只换了 `:root` 变量其实不够**：

- 真正的画布底色不在 `--canvas-bg`，而在 `.bg-ambient` 里**硬编码的 `#0b0908` + 7 层琥珀色径向渐变**（盖在 `--canvas-bg` 之上）。所以只改变量，画面纹丝不动。
- 把暖琥珀光晕换成中性白（结构与 26s 呼吸动效保留），`html/body` 的 `#000` 换成 `--canvas-bg`，其余按第 1/8/11 节的 Notion 取值替换。
- **`--axis-line` 在 CSS 里被引用 0 次**——它的轴线颜色是写死的。`:root` 之外共有 **229 处硬编码颜色**，属于阶段 2 的清理范围。
- **纪元色带（`.t-blue` 等 6 套 `--cs/--cb/--cf`）没有动**：它们是内容语义色（用户在编辑器里选的纪元身份），且是逐像素对着录屏复刻的基准。要换成 Notion 色板需单独决策。
